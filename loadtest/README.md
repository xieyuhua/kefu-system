# HTTP 压测台（AI 编排版）

给它一个地址，剩下的交给 AI 和你：

```
① 给地址 → 自动勘察接口，AI 整理成清单
② 你勾选要压的接口（并发、间隔都能改，先「试跑」验证单条）
③ 跑压测 → 实时吞吐/延迟/错误 + 分接口明细 + 逐秒日志
④ AI 读这轮指标 → 瓶颈定位 + 按 P0/P1/P2 排的整改优化方案
```

- 独立 Go 项目，单 exe，零外部依赖（除 WebSocket 库），内置页面不用 Node 构建
- 大模型可选：任意 OpenAI 兼容接口（DeepSeek / 通义 / Moonshot / OpenAI）；
  **不配置也能用**，会自动回退到内置规则引擎（勘察、分析、整改建议都照常出）
- 也可以纯命令行跑，退出码非 0 即不通过，方便接 CI

## 目录

```
loadtest/                     独立 Go 模块（不影响 server/ 和 web/）
├─ main.go                    入口：Web 控制台 / CLI
├─ internal/config/           压测参数（多接口场景）与校验
├─ internal/discover/         地址勘察：探活 / OpenAPI / 已知模式 / 页面扫描 + AI 整理
├─ internal/aiclient/         OpenAI 兼容大模型客户端（含 JSON 容错解析）
├─ internal/advise/           结果分析 + 整改方案（规则引擎 + AI）
├─ internal/engine/           并发引擎（多场景、爬坡、初始化、长连接）与报告
├─ internal/metrics/          指标采集（每秒分桶、延迟直方图、错误聚合）
├─ internal/console/          控制台接口、任务管理、连通性自检、报告落盘
├─ internal/logbus/           实时日志环形缓冲
├─ web/                       内置控制台页面（原生 HTML/CSS/JS）
├─ msgs.txt                   示例消息文件（CLI 用，一行一条）
└─ reports/                   报告输出：run-*.json / run-*.csv / advice-*.md
```

## 快速开始

```powershell
cd loadtest
go run .                      # 打开 http://127.0.0.1:8600
# 或者双击/执行
.\start-loadtest.ps1
```

页面操作：

1. 填 **目标地址** → 点 **让 AI 分析接口**
   - 可以填接口基址 `http://127.0.0.1:8480`
   - **也可以直接粘前端页面地址**，例如 `http://127.0.0.1:8480/kefu/?channel=kefu_1edcf1a9&uid=20261022094940#/`：
     会自动解析出「接口基址 = http://127.0.0.1:8480」「渠道 = kefu_1edcf1a9」「客户 ID = 20261022094940」，
     并把目标地址回填成接口基址
2. 勘察记录会列出它看到了什么（地址解析、探活、识别到的访客链路、扫到的接口…）
3. 在 **② 勾选要压的接口** 里勾选（推荐项默认已勾），可改并发/间隔，可展开「参数」改路径和请求体，
   每个接口都能点 **试跑** 先验证一条能不能通过
4. 设好 **运行时长**，点 **开始压测**；右侧看实时指标、分接口表现、逐秒日志和曲线
5. 跑完点 **④ 分析这轮结果** → 得到瓶颈定位 + 整改方案，可下载 `整改建议 .md`

### 用链接直达

```
http://127.0.0.1:8600/?target=http://127.0.0.1:8480&auto=1        # 自动勘察
http://127.0.0.1:8600/?target=...&auto=1&advice=1                # 顺便把上轮结果也分析了
```

## 接大模型（可选）

页面右上角 **AI 设置** 填三项即可，也支持环境变量 / CLI 参数：

| 方式 | 配置 |
|---|---|
| 页面 | AI 设置 → `base_url` / `model` / `api_key`（密钥只在内存里，回显已脱敏） |
| 环境变量 | `KEFU_LT_AI_BASE_URL`、`KEFU_LT_AI_KEY`、`KEFU_LT_AI_MODEL` |
| 命令行 | `-ai-base`、`-ai-key`、`-ai-model` |

常见写法：

```powershell
$env:KEFU_LT_AI_BASE_URL="https://api.deepseek.com/v1"
$env:KEFU_LT_AI_KEY="sk-xxx"
$env:KEFU_LT_AI_MODEL="deepseek-chat"
go run .
```

不配置时，勘察与分析走内置规则，页面和日志里会标明「来源：内置规则」。

## AI/规则到底做了什么

### 第一步：勘察（全部只读，不写业务数据）

| 手段 | 说明 |
|---|---|
| 地址解析 | 支持直接粘前端页面地址：拆出接口基址、渠道、客户 ID（`?channel=&uid=&tenant=`），带路径前缀的接口基址（如 `/api/v1`）会保留 |
| 探活 | `GET <基址>/`，记录状态码、耗时、Content-Type、大小 |
| OpenAPI 契约 | 依次探 `/openapi.json`、`/swagger.json`、`/v2/api-docs`、`/api-docs` 等，命中就按 path + method 全量列出（含鉴权判断） |
| 已知模式 | 命中客服系统访客链路（`/api/guest/init` 返回 `code=0`）时，直接给出「访客发消息 / 打开聊天页 / 拉取消息 / 客服登录 / 数据统计」候选 |
| 页面 + 脚本扫描 | 抓页面 HTML 与它引用的 JS，**顺着 `import("./Xxx.js")` 把懒加载 chunk 也扫一遍**；既找 `/api/...` 字面量，也解析 axios 风格 `.(get\|post)('/guest/init')` 调用并用 `baseURL` 补全前缀（很多 SPA 就是这种写法，页面上看不到 `/api`） |

然后把这些事实 + 候选交给 AI，让它补上**中文名、业务用途、风险等级（只读/写入/危险）、建议并发与间隔、
是否需要先初始化会话、是否需要登录 Token、是否推荐压测、压测注意事项**。
AI 不可用时用同一套规则生成（风险等级、初始化/鉴权判断都是本地完成的，不依赖 AI）。

### 第四步：分析（只用真实指标，不让模型编数据）

喂给 AI 的是结构化指标：总并发、发起/成功/失败、在途、吞吐、P50/P95/P99/最大、错误类型分布、
每个接口的独立指标。输出固定四节：**一句话结论 / 瓶颈定位 / 整改优化方案（P0-P2，写清怎么改与怎么验证） / 复测建议**。

内置规则会按错误类型给出对应诊断与整改动作，例如：

- `timeout` → 慢查询日志、SQLite 单写锁换 MySQL/开 WAL、连接池 max_open、异步化、热点缓存
- `conn_refused / conn_reset` → 进程是否崩溃、`ulimit -n`、监听 backlog、TIME_WAIT、压测机端口耗尽
- `http_5xx` → 按时间点拉服务端日志定位堆栈
- `http_429` → 限流阈值与压测目标不匹配
- `http_404 / biz_error` → 先修用例（路径、参数、鉴权），别把用例错误当性能问题

## 参数说明

### 每个接口（在勾选表里改）

| 字段 | 说明 |
|---|---|
| 路径 | 支持占位符 `{{uid}} {{channel}} {{seq}} {{ts}} {{rand6}} {{nick}}` |
| 请求体 | JSON 模板，同样支持占位符；GET 可留空 |
| 并发 | 该接口的虚拟用户数（多个接口的并发相加 = 总并发） |
| 间隔 ms | 同一用户两条请求之间的间隔（0 = 全速） |
| 先调用访客初始化 | 勾上则每个并发在发请求前先 `GET /api/guest/init` 建会话（客服系统必需） |
| 需要登录 Token | 勾上则请求带 `Authorization: Bearer <Token>`，Token 在下方统一填 |

### 全局

| 字段 | 说明 |
|---|---|
| 运行时长 | 秒；也可以给每个接口设「每并发条数」按条数跑（CLI `-n`） |
| 爬坡 | 毫秒内把所有并发逐个拉起（0 = 瞬间，秒建连接容易把压测机打出问题） |
| 超时 | 单请求超时（毫秒） |
| 客户 ID 前缀 | 压测客户 ID 前缀，便于后台按前缀清理压测数据 |
| WebSocket | 对需要初始化的接口额外维持 `/ws/guest` 长连接，验证推送稳定性 |
| 长连接复用 | 关闭则每条请求新建 TCP 连接（用来观察 TIME_WAIT/句柄压力） |

## 指标口径

| 指标 | 含义 |
|---|---|
| 发起请求 | 真正发出去的请求数（**按发出时刻**统计，反映施压速率） |
| 成功 / 失败 | 按**完成时刻**统计；2xx 且（响应体是 JSON 时 `code==0`）算成功，3xx/4xx/5xx 与业务码非 0 都算失败 |
| 失败率 | 失败 /（成功 + 失败），只算已经回来的请求 |
| 未完成（在途） | 压测结束时仍未返回的请求，单独展示、不计入成功率 |
| 平均 / P50 / P90 / P95 / P99 / 最大 | 端到端耗时，直方图统计 |
| 分接口表现 | 每个接口独立的发起/失败率/延迟，用来定位是谁在拖后腿 |
| 错误分布 | 按「类型 + 详情」聚合：timeout / conn_refused / conn_reset / http_5xx / biz_error … |

> 曲线只画**已经走完的整秒**（未满一秒的点会把曲线尾部拉低），另可开「平滑曲线」（5 点滑动平均，仅影响显示，CSV 里是原始值）。

## 命令行

```powershell
# 单接口直压（默认打访客发消息链路）
go run . -cli -c 20 -duration 30 -msg "你好，我想咨询发货时间"

# 指定任意接口 + 请求体，带 Token，跑完自动出分析
go run . -cli -target https://api.example.com -c 50 -duration 60 `
  -method POST -path "/api/orders?uid={{uid}}" -body '{"sku":"A1","n":1}' -skip-init

# 多条消息轮流发、同时校验 WebSocket
go run . -cli -c 20 -duration 60 -msg-file msgs.txt -ws
```

退出码：`0` 通过 / `2` 不通过（失败率或延迟超阈值）。

## 报告

| 文件 | 内容 |
|---|---|
| `reports/run-<时间>.json` | 全部参数、总指标、分接口指标、错误分类、稳定性结论 |
| `reports/run-<时间>.csv` | 每秒时序（发起/成功/失败/平均延迟），可直接做趋势图 |

## 全部失败了怎么排查

1. 点 **连通性/试跑**：连不上 = 端口地址错或服务没起；`code=400 渠道不存在` = 渠道没启用；`404` = 路径不对
2. 看 **错误分布 + 实时日志**：`timeout` 是慢，`conn_refused` 是服务没在跑，`biz_error` 是参数/鉴权不对
3. 勾了 **需要登录 Token** 但没填 Token，会在启动前直接报错提示
4. 全新客户 ID 又勾了「跳过初始化」→ 服务端没有会话，必然 100% 失败

## 接口清单不够全怎么办

勘察记录会逐条说明它做了什么，按情况处理：

| 勘察记录里看到 | 说明与做法 |
|---|---|
| 只列出「探活」和「已知模式」，没有页面扫描 | 前端接口不是静态字面量（比如路径全由变量拼接）。把目标地址换成**带渠道参数的页面地址**（`?channel=xxx`），或手工在候选里点「参数」补路径 |
| 页面扫描 0 个接口，但记录里显示扫了 N 个脚本 | 该页面需要登录才能加载业务 chunk：先登录后再粘带 token 的页面地址，或直接用 OpenAPI 文档 |
| 有 OpenAPI 但只找到少量接口 | 契约里的鉴权接口默认不勾（需要 Token），填上下方 Token 后即可勾选压测 |
| 接口列表和你在浏览器开发者工具里看到的不一致 | 用「试跑」逐个验证；也可以直接把候选的「参数 → 路径」改成分包抓到的真实路径 |

## 注意事项

- 压测机与被测服务尽量分开两台，否则压测机会先成瓶颈（CPU/端口/句柄）
- 并发上千时保持 HTTP 长连接复用，注意本机 `MaxUserPort` 限制
- 压测会产生真实数据：建议独立 `uid_prefix`，压完按前缀清理；危险接口（DELETE 等）默认不勾选
- 页面扫描出来的路径只是「可能存在的接口」，盲压会大量 4xx，先「试跑」再勾
