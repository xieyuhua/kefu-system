# 后端分层架构

> 目标：职责单一、依赖单向。**HTTP 层不碰数据库，业务层不写 SQL。**

## 分层总览

```
请求 → route → handler → service → repository → model/DB
                    ↑         ↓
                   dto   response
```

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| **route** | `internal/route` | 注册 URL、挂中间件、按权限分组 | 写业务逻辑 |
| **handler** | `internal/handler` | 解析参数 → 调 service → 写响应 | 直接访问数据库（GORM） |
| **service** | `internal/service` | 业务校验、编排、事务边界、领域规则 | 拼接 GORM 查询 |
| **repository** | `internal/repository` | 所有 GORM 查询与写入 | 包含业务判断 |
| **model** | `internal/model` | GORM 实体定义 | 依赖上层 |

配套：
- `internal/dto` —— 出入参结构与视图对象（VO）
- `internal/response` —— 统一响应壳 `{code, message, data}`
- `internal/middleware` —— JWT 鉴权、跨域、恢复
- `internal/config` / `internal/db` / `internal/cache` / `internal/auth` / `internal/seed` —— 基础设施

## 依赖方向

```
route    → handler → service → repository → model
                            ↘ dto / response（纯数据结构，无副作用）
```

- 上层可以依赖下层，**下层不得反向依赖上层**。
- `repository` 只认 `model`，不认识 `dto`。
- `service` 负责把 `model` 组装成 `dto` 视图对象。

## repository 使用约定

```go
// 连接由 main 在启动时注入一次
repository.SetDB(db.DB)

// 仓储函数按领域分文件：channel.go / channel_type.go / tenant.go / user.go /
// conversation.go / message.go / customer.go / order.go / product.go /
// tag.go / setting.go / stats.go / autoreply.go / notification.go

// 事务：跨表写入要求原子性时使用
err := repository.Tx(func(tx *gorm.DB) error {
    if err := repository.CreateMessage(tx, &m); err != nil { return err }
    return repository.UpdateConversationSummary(tx, convID, preview)
})
```

命名规范：

| 前缀 | 语义 | 返回 |
|---|---|---|
| `Find*` | 查单条，找不到返回错误 | `(*model.X, error)` |
| `List*` | 查多条 | `([]*model.X, error)` |
| `Count*` | 计数 | `(int64, error)` |
| `Create*` | 新增 | `error`（或回填 ID 后的实体） |
| `Save*` / `Update*` | 更新 | `error` |
| `Delete*` | 删除 | `error` |

## 指针使用约定

为**避免整行结构体拷贝**（`model.*` 含 10+ 字段，列表动辄上百行），全仓统一按指针传递：

```go
// 单条查询返回指针
func FindUserByID(tenantID, id uint) (*model.User, error)

// 列表返回指针切片（GORM 原生支持 var list []*T + Find(&list)）
func ListUsersByTenant(tenantID uint) ([]*model.User, error)

// 写入接收指针，回填主键后调用方可直接用
func CreateChannel(c *model.Channel) error
func SaveConversation(c *model.Conversation) error

// 只读的领域辅助函数也收指针，调用点无需取址/解引用
func BuildOrderCard(o *model.Order) string
func buildConversationVO(c *model.Conversation) dto.ConversationVO
func ChannelKey(c *model.Channel) string
```

要点：

- 仓储**查询**一律返回指针（单条 `*T`，列表 `[]*T`），调用方遍历 `for _, x := range list` 时 `x` 即指针，字段访问与传参都无需转换。
- 仓储**写入**一律接收指针，便于 `Create` 回填自增主键与时间戳。
- Go 1.22+ 循环变量按迭代独立，`for _, x := range list { out = append(out, &x) }` 不会出现指针别名问题（本项目 go 1.26）。
- 值类型仅用于纯标量参数（id、字符串、分页）与 `dto` 视图对象。

## GORM 收敛现状

`gorm` 只出现在以下位置，其余各层零 GORM：

| 位置 | 用途 |
|---|---|
| `internal/repository/*.go` | 全部业务数据访问 |
| `internal/db/db.go` | 连接建立与驱动选择 |
| `main.go` | `repository.SetDB(db.DB)` 注入一次 |
| `internal/seed/*.go` | **例外**：启动时的一次性演示数据引导，属基础设施，不参与请求链路 |

`service` 与 `handler` 两层已无 `gormDB()` / `db.DB` / GORM 链式调用。
websocket（`hub.go`）、推送（`push.go`）、IP 归属（`ipinfo.go`）等横切逻辑也统一经 repository 取数。

## 已知可继续收口项

- `service.ResolveGuestChannel` 用「取租户渠道列表 + 内存三级匹配（app_id → type → 数字 ID）」解析接入链接的 `channel` 参数。
  渠道数量很小，成本可接受；如需纯 SQL 化，可在 `repository/channel.go` 增加 `FindChannelByAccessKey`。

## 新增一个接口的标准动作

1. `repository/x.go`：写数据访问函数（唯一出现 `gorm` 的地方）
2. `service/x.go`：写业务函数，调用 repository，返回 `dto`
3. `handler/x.go`：解析参数、调 service、`response.OK/Param/Forbid`
4. `route/router.go`：注册路由（注意 `/xxx/:id` 之前先注册静态路径）

## 目录一览

```
server/
  main.go                 启动：配置 → DB → 缓存 → 种子数据 → 路由
  internal/
    route/                路由注册
    handler/              HTTP 处理（原 api/）
    service/              业务逻辑，按域分文件
    repository/           数据访问，按域分文件
    model/                实体
    dto/                  出入参 / VO
    response/             统一响应
    middleware/           中间件
    auth/  cache/  config/  db/  seed/   基础设施
```
