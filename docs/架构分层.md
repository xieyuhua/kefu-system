# 后端分层架构

> 组织方式：**业务模块优先，模块内再按技术分层**。
> 一个业务改动只进一个模块目录；跨模块依赖必须单向，禁止循环。

## 总体结构

```
server/
  main.go                     启动装配：config → db → seed → route
  internal/
    route/router.go           路由汇总（唯一的路由真值来源）
    platform/                 基础设施（被所有模块依赖，自己不依赖任何模块）
    modules/                  业务模块（8 个）
```

`internal/` 的语义：整个仓库外部的包不可导入这些代码。

## platform —— 基础设施

| 包 | 职责 |
|---|---|
| `model` / `dto` | 数据实体；出入参与视图对象 |
| `storage` | 数据库连接与事务：`SetDB` / `DB()` / `Tx()` / `Paginate` |
| `setting` | 租户级配置（默认图片、提示音） |
| `card` | 订单/商品卡片 JSON 构造（纯函数） |
| `idgen` | 渠道 `app_id` 生成与唯一性校验 |
| `util` | 时间格式化等通用小工具 |
| `httpx` | gin 辅助：claims 解析、当前用户、参数绑定 |
| `realtime` | WebSocket Hub、事件发布、站内通知、厂商推送 |
| `ipinfo` | IP 归属地解析 |
| `response` / `middleware` / `auth` / `cache` / `config` / `db` / `seed` | 响应壳、JWT 中间件、密码与 token、缓存、配置、连接、演示数据 |

platform **不得** import 任何模块。需要反向能力时用回调注入，例如：

```go
// realtime 定义钩子，业务侧注册
realtime.SetAgentOfflineHook(chat.ReleaseAgentConversations)
httpx.SetUserLoader(account.LoadUser)
```

## modules —— 业务模块

每个模块统一为 `handler.go` / `service.go` / `repository.go`（无接口约定的模块可省略）：

| 模块 | 负责的业务 | 主要数据表 | 依赖 |
|---|---|---|---|
| `account` | 登录、个人资料、子账号 | users、agent_channels | platform |
| `channel` | 渠道、渠道类型、二维码 | channels、channel_types | platform |
| `customer` | 客户、标签、订单、商品 | customers、tags、orders、products | platform |
| `chat` | 会话、消息、WebSocket | conversations、messages | account、channel、customer |
| `guest` | 用户端接入（免登录） | 经 customer/chat 写入 | chat、customer、channel、automation |
| `automation` | 自动回复规则与转人工 | auto_replies | chat |
| `ops` | 系统设置、统计、通知、设备、演示 | settings、notifications、devices | chat、customer、automation |
| `upload` | 文件上传 | — | guest |

### 模块内三层职责

| 文件 | 职责 | 禁止 |
|---|---|---|
| `handler.go` | 解析参数 → 调 service → 写响应 | 直接访问数据库 |
| `service.go` | 校验、编排、事务边界、DTO 组装 | 拼接 GORM 查询 |
| `repository.go` | 本模块数据访问 | 跨模块业务判断 |

- handler 函数统一带 `Handler` 后缀（`account.LoginHandler`），避免与同包 service 同名冲突。
- repository **可读任意表**，但**只写本模块自己的表**。跨模块需要写入时，调用对方 service。
- 少量「跨模块只读」查询会就地实现（如 `customer` 统计会话数直接读 conversations），文件头注明原因，以此避免反向依赖。

## 依赖方向

```
platform  ←  account / channel / customer  ←  chat  ←  guest / automation / ops / upload
```

- 上层可依赖下层，**下层不得反向依赖上层**。
- 判断是否违规最快的方法：`go build ./...` —— 出现 import cycle 即说明方向错了。

## 新增一个接口的标准动作

1. 判断属于哪个模块（按业务，不按表）。
2. `modules/<m>/repository.go`：加数据访问函数（唯一出现 GORM 的地方）。
3. `modules/<m>/service.go`：加业务函数，返回 `dto`。
4. `modules/<m>/handler.go`：加 `XxxHandler`，解析参数、调 service、`response.OK/Param/Forbid`。
5. `route/router.go`：注册路由（注意 `/xxx/:id` 之前先注册静态路径）。

## 命名规范

| 前缀 | 语义 | 返回 |
|---|---|---|
| `Find*` | 查单条，找不到返回错误 | `(*model.X, error)` |
| `List*` | 查多条 | `([]*model.X, error)` |
| `Count*` | 计数 | `(int64, error)` |
| `Create*` / `Insert*` | 新增 | `error` |
| `Save*` / `Update*` | 更新 | `error` |
| `Delete*` / `Remove*` | 删除 | `error` |

## 指针使用约定

避免整行结构体拷贝（`model.*` 含 10+ 字段）：

```go
func FindUserByID(tenantID, id uint) (*model.User, error)      // 单条 → 指针
func ListUsersByTenant(tenantID uint) ([]*model.User, error)   // 列表 → 指针切片
func CreateChannel(c *model.Channel) error                     // 写入 → 收指针
func BuildOrderCard(o *model.Order) string                     // 只读辅助 → 收指针
```

Go 1.22+ 循环变量按迭代独立，`for _, x := range list { out = append(out, &x) }` 无指针别名问题（本项目 go 1.26）。

## GORM 收敛现状

`gorm` 只出现在：

| 位置 | 用途 |
|---|---|
| `modules/*/repository.go` | 业务数据访问 |
| `platform/storage` / `platform/db` | 连接建立与事务 |
| `platform/realtime/store.go`、`platform/ipinfo`、`platform/idgen`、`platform/setting` | 基础设施少量直写（文件头注明例外） |
| `main.go` | `storage.SetDB(db.DB)` 注入一次 |
| `platform/seed` | 启动时一次性演示数据引导 |

`handler` 与 `service` 两层不含任何 GORM 调用。
