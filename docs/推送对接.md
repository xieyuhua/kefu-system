# APP / PC 桌面端 推送对接文档

本文说明如何把「客服系统的消息与提醒」推送到用户的 **APP** 和 **PC 桌面端**，以及离线时如何保证消息不丢。

## 1. 整体架构

```
                        ┌──────────────── 客服系统后端 ────────────────┐
                        │                                            │
  APP / PC 桌面端        │   ① POST /api/devices  注册推送 Token      │
       │                │   ② /ws  长连接（在线时实时推送）           │
       │  注册 token     │   ③ PushGateway.Send  厂商推送（离线时）    │
       ├───────────────►│   ④ Notification 落库（兜底）              │
       │                │                                            │
       │  长连接断开     │   端侧重连时 GET /api/offline/notifications │
       │◄───────────────┤              拉取离线期间堆积的提醒         │
       │  收到系统通知   │                                            │
       ▼                └────────────────────────────────────────────┘
```

**两条通道互补**，任何一条不通都不会丢消息：

| 通道 | 触发时机 | 可靠性 | 覆盖 |
|---|---|---|---|
| WebSocket 长连接 | 用户在线 | 实时（毫秒级） | 工作台 / APP / PC 三端共用 `/ws` |
| 厂商推送 | 用户离线 | 秒级 | APP（通知栏）、PC（系统托盘） |
| 离线补拉 | 用户重连后 | 立即 | 全部端（`/api/offline/*`） |

## 3. 第一步：设备注册（端侧调用）

APP / PC 端启动或登录后，调用一次注册接口，把推送 Token 告诉服务端。

```http
POST /api/devices
Authorization: Bearer <客服的 JWT>
Content-Type: application/json

{
  "device": "app",           // app | desktop | web
  "platform": "ios",         // ios | android | windows | mac
  "push_token": "a1b2c3...", // 厂商下发的推送 Token
  "name": "iPhone 15"        // 设备名，后台列表展示用
}
```

响应：

```json
{
  "code": 0,
  "data": {
    "id": 12,
    "device": "app",
    "platform": "ios",
    "name": "iPhone 15",
    "push_token": "a1b2c3...",
    "created_at": "2026-03-05 10:22:11"
  }
}
```

### 3.1 各平台 Token 从哪来

| 平台 | Token 获取方式 |
|---|---|
| iOS | APNs 推送 Token（需 `aps-environment` 权限） |
| Android | 厂商通道 Token（小米/华为/OPPO/vivo）或 FCM Token |
| PC 桌面端 | 一般**不需要**厂商推送 Token，只走 WebSocket；如需离线提醒可用 Electron 的 `Notification` + 主进程托盘 |
| Web | **无需**注册，浏览器端由 `Notification` API 自行处理（见 §5.3） |

### 3.2 注销设备

用户登出、卸载、换机时调用：

```http
DELETE /api/devices/12
```

后台「设备管理」页也可以手动注销。

### 3.3 代码调用示例（APP 启动时）

```typescript
// 伪代码：登录成功后注册设备
async function registerDevice(token: string) {
  const pushToken = await getVendorPushToken()  // 各平台自行获取
  if (!pushToken) return
  await http.post('/api/devices', {
    device: 'app',
    platform: 'ios',
    push_token: pushToken,
    name: deviceName(),
  })
}
```

## 4. 第二步：实现厂商推送

这是**唯一需要开发的部分**。打开 `server/internal/service/push.go`，把 `Send()` 的占位实现替换为真实调用。

### 4.1 当前占位代码

```go
func (p *PushGateway) Send(tenantID, userID uint, n model.Notification) {
    var devices []model.Device
    db.DB.Where("tenant_id = ? AND user_id = ?", tenantID, userID).Find(&devices)
    if len(devices) == 0 { return }   // 完全离线 → 等重连后拉取
    for _, d := range devices {
        if d.PushToken == "" { continue }
        // TODO(接入厂商推送): 调用 APNs / 极光 / 个推 的 HTTP API 下发
        log.Printf("[push] -> device=%s ...", d.Device, d.Platform, d.PushToken, n.Title, n.Body)
    }
}
```

### 4.2 接入点说明

`Send()` 已经帮你做好了这些事，你只要专注发推送：
- 按租户 + 用户查出该用户的**所有设备**
- 跳过没有 Token 的设备
- 推送内容来自 `model.Notification`（`Title` / `Body` / `Type` / `ConversationID`）

**建议的改造**：把厂商调用抽成可插拔的 provider，便于同时接多家：

```go
// server/internal/service/push.go（改造示例）

// Provider 抽象一个厂商推送通道
type Provider interface {
    Name() string
    // Push 向单个设备下发；返回是否成功（失败时可清理失效 Token）
    Push(d model.Device, n model.Notification) error
}

// 注册多个 provider（按 device.platform 路由）
var providers = map[string]Provider{}

// 初始化时注册（server/main.go）
func initPush() {
    providers["ios"] = NewAPNsProvider(...)   // github.com/sideshow/apns2
    providers["android"] = NewJPushProvider(...) // 极光 SDK
}

func (p *PushGateway) Send(tenantID, userID uint, n model.Notification) {
    var devices []model.Device
    if err := db.DB.Where("tenant_id = ? AND user_id = ?", tenantID, userID).Find(&devices).Error; err != nil {
        return
    }
    if len(devices) == 0 {
        return // 无设备 → 提醒已落库，等重连后拉取
    }
    for _, d := range devices {
        if d.PushToken == "" {
            continue
        }
        prov, ok := providers[d.Platform]
        if !ok {
            continue // 该平台未接厂商推送，只靠 WebSocket
        }
        if err := prov.Push(d, n); err != nil {
            log.Printf("[push] %s 推送失败 device=%d: %v", prov.Name(), d.ID, err)
            // 可选：厂商返回 token 失效错误码时，清理该设备记录
            // if isTokenInvalid(err) { db.DB.Delete(&model.Device{}, d.ID) }
        }
    }
}
```

### 4.3 各厂商接入要点

| 厂商 | Go SDK / 方式 | 说明 |
|---|---|---|
| **APNs（iOS）** | `github.com/sideshow/apns2` | 需 `.p8` 密钥（Key ID / Team ID / Bundle ID），HTTP/2 下发 |
| **极光 JPush** | `github.com/jpush/jpush-api-go-client` | 支持 iOS + Android 一套接口，国内最常用 |
| **个推 GeTui** | `github.com/getuistock/https-push-go` | 国内另一主流 |
| **FCM（海外）** | 直接调 FCM HTTP v1 API | Google 官方 |
| **华为 HMS / 小米 / OPPO / vivo** | 各家 Web 端 API | 国内 Android 需各自通道，且要保证 App 后台存活 |

> **通道存活提示**：国内 Android 厂商推送在应用被系统杀死时仍能送达（各家保活机制），但 iOS 的 APNs 在 App 完全退出后**只有 Remote Notification 才会到通知中心**，需要你在 App 端注册 `didRegisterForRemoteNotifications`。

### 4.4 推送内容建议

| 字段 | 建议值 |
|---|---|
| `title` | 通知类型，如「新消息」「待接待提醒」 |
| `body` | 客户昵称 + 消息摘要，如「王小明：这个什么时候发货？」 |
| `click_action` | 点击后跳转的会话 ID（`n.ConversationID`），端侧据此定位到具体会话 |
| `sound` | 默认 |

## 5. 第三步：PC 桌面端（Electron）

PC 桌面端通常**不需要厂商推送**，直接复用 WebSocket 即可。两点注意：

### 5.1 连接时标明端类型

```
ws://host/ws?token=<jwt>&device=desktop
```

### 5.2 离线提醒（可选）

Electron 主进程可用系统通知，无需第三方 SDK：

```javascript
// Electron 主进程
const { Notification } = require('electron')
new Notification({
  title: '新消息',
  body: '王小明：这个什么时候发货？',
}).show()
```

触发时机：WebSocket `disconnected` 后，由渲染进程轮询 `/api/offline/notifications`（`since_id` 增量），有数据就弹系统通知。

### 5.3 Web 端（浏览器）

Web 工作台已内置浏览器通知（工作台首次进入会请求授权）：

```typescript
new Notification('新消息', { body: '王小明：...', tag: String(conversationId) })
```

## 6. 离线消息与补偿

推送是「尽力而为」的通道（可能被系统限流、用户关通知），所以**真正的可靠性来自离线补拉**。

### 6.1 离线提醒补拉

端侧重连后拉取离线期间堆积的提醒：

```http
GET /api/offline/notifications?since_id=0
```

响应：

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 3,
        "type": "conversation.transferred",
        "title": "会话转接",
        "body": "有一条会话被转接给你",
        "conversation_id": 11,
        "read": false,
        "created_at": "2026-03-05 14:00:00"
      }
    ],
    "latest_id": 3
  }
}
```

标记已读：

```http
POST /api/offline/notifications/read
{ "ids": [1,2,3] }
```

### 6.2 离线消息增量补拉

如果端侧还要补齐**消息本身**（而不只是提醒）：

```http
GET /api/offline/messages?since_id=0&limit=200
```

- `since_id` 为**正向游标**：返回 `id > since_id` 的消息
- 响应里的 `latest_id` 存下来，作为下次拉取的起点
- 不会重、不会漏

### 6.3 端侧保存游标

```typescript
// 每次拉取后保存
localStorage.setItem(`kf_notif_${userId}`, data.latest_id)
```

或（推荐）存服务端/用户偏好，多端同步。

## 7. 完整对接检查清单

- [ ] **后端**：在 `server/internal/service/push.go` 实现 `Send()`，替换日志占位
- [ ] **后端**：在 `main.go` 初始化时注册厂商 provider（`initPush()`）
- [ ] **后端**：`config.yaml` 里补上厂商配置（如 `app_id` / `secret` / `key_file`）
- [ ] **APP**：登录后调用 `POST /api/devices` 注册推送 Token
- [ ] **APP**：WebSocket 连 `/ws?token=...&device=app`
- [ ] **APP**：重连时调用 `/api/offline/messages?since_id=` 和 `/api/offline/notifications?since_id=`
- [ ] **APP**：收到推送点击后，根据 `conversation_id` 跳到对应会话
- [ ] **PC 桌面端**：连接 `/ws?device=desktop`（如需离线提醒，加 `/api/offline/notifications` 轮询 + Electron 主进程通知）
- [ ] **Web**：确认浏览器通知授权（工作台已内置）
- [ ] **联调**：用两个端（一个在线、一个离线）验证：在线端实时收到、离线端收到系统通知、重连后不重复

## 8. 常见问题

**Q：推送发了但用户没收到？**
按顺序排查：① 设备是否注册成功（后台「设备管理」能看到）；② 该平台的 provider 是否已注册且 SDK 凭据正确；③ 用户是否在系统设置里关了通知权限；④ iOS 是否在后台注册了 `didRegisterForRemoteNotifications`；⑤ 是否在模拟器上测（模拟器拿不到真 Token）。

**Q：多端登录会不会重复收到？**
会。每个设备都注册了一条记录，都会收到推送。若需「只推最新登录的端」，可在 `Device` 上记录登录时间，只推最新，或引入「设备互斥登录」策略。

**Q：为什么已有 WebSocket 还要推送？**
WebSocket 只在 App 存活时可靠。用户息屏、切后台被系统回收进程、或 PC 关机时，只有厂商推送能触达。

**Q：推送内容会泄露隐私吗？**
通知栏内容会显示在锁屏上。敏感场景建议 `body` 留空或写「您有一条新消息」，点开后再拉详情。

**Q：如何调试推送？**
`push.go` 里的 `log.Printf` 会打印每次推送的设备与内容，开启 `mode: debug` 后在服务端日志里查看。把日志级别改成 `release` 前确认凭据不会被打到日志里。
