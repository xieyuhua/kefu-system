# 客服系统部署教程

面向运维/开发同学的完整部署指南，覆盖 **单机独立部署** 与 **分布式部署** 两种形态。

- 单机独立部署：一个后端进程 + MySQL（Redis 可选），适合中小规模、快速上线
- 分布式部署：Nginx 静态站点 + 多个后端实例 + 共享 MySQL/Redis，适合多客服并发、需要高可用

---

## 0. 三种形态对比

| 形态 | 适用场景 | 后端进程 | Redis | 前端资源 | WebSocket |
|---|---|---|---|---|---|
| 开发调试 | 本地改代码 | `go run .` | 可选 | `pnpm dev`（5173） | 直连后端 |
| 单机独立部署 | 单台服务器、几十个客服 | 1 个 | 可选（不启用自动降级为内存） | 由后端托管 `web/` | 单实例 |
| 分布式部署 | 多台服务器、高可用、上量 | ≥2 个 | **必须** | Nginx 直出 | Redis Pub/Sub 跨实例广播 |

> 关键差异：**只有多实例时才必须启用 Redis**。Redis 承担 4 件事：
> 1. WebSocket 事件跨实例广播（频道 `events` 客服端 / `guest-events` 访客端）
> 2. Token 吊销黑名单（退出登录后旧 token 立即失效）
> 3. 客服在线状态与会话并发锁
> 4. 会话/客户资料的读缓存
>
> 单机不启用 Redis 时，以上全部自动降级为进程内内存实现，功能不受影响。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Go | 1.26+ | 仅构建机需要；也可在 CI 里构建后只分发二进制 |
| Node.js | 20+ | 构建前端 |
| pnpm | 10+ | `npm i -g pnpm` |
| MySQL | 8.0+ | **必须 utf8mb4**（否则表情符号写入报 1366） |
| Redis | 6+ | 分布式部署必需；单机可选 |
| Nginx | 1.20+ | 单机可选（直接暴露后端也行），分布式必需 |

端口约定：

| 端口 | 用途 | 是否对外 |
|---|---|---|
| 8480 | 后端 HTTP/WS | 单机可对外；分布式只对 Nginx 开放 |
| 80 / 443 | Nginx | 对外 |
| 3306 | MySQL | 仅后端可访问 |
| 6379 | Redis | 仅后端可访问 |

## 2. 构建

### 2.1 前端

```bash
cd web
pnpm install
pnpm build          # 产物默认输出到 ../server/web
```

自定义输出目录：

```bash
OUT_DIR=/opt/kefu/web pnpm build
```

产物包含 4 个入口：`index.html`（用户端）、`admin.html`、`chat.html`、`kefu.html`，以及 `assets/`、`img/`、`favicon.svg`、`icons.svg`。

> 构建结束时若出现 `chunk larger than 500 kB` 警告属于正常现象（Element Plus 体积），不影响产物。

### 2.2 后端

```bash
cd server
go build -ldflags="-s -w" -o kefu-server .
```

- Linux 上得到 `kefu-server`
- Windows 上得到 `kefu-server.exe`
- 交叉编译：`GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o kefu-server .`

> ⚠️ Windows 上**必须**带 `-ldflags="-s -w"`：使用 cgo（go-sqlite3）时，未 strip 的二进制会把 DWARF 段放到 `0xFFC00000`，超出 `SizeOfImage`，Windows 加载器直接拒绝启动，报「不是有效的 Win32 应用程序」。

### 2.3 部署目录布局

后端按「可执行文件所在目录」查找资源，最终目录必须长这样：

```
/opt/kefu/                  # 工作目录
├── kefu-server             # 后端二进制
├── config.yaml             # 配置文件
├── web/                    # 前端产物（pnpm build 输出）
│   ├── index.html
│   ├── admin.html
│   ├── chat.html
│   ├── kefu.html
│   ├── assets/
│   └── img/
└── data/
    ├── uploads/            # 上传文件（启动时自动创建）
    └── demo/               # 演示素材（可选，渠道示例图等）
```

资源查找顺序（可用环境变量强制指定）：

1. `KEFU_WEB_DIR` 环境变量
2. 可执行文件同级 `web/`
3. 当前工作目录 `web/`

## 3. 配置文件

`config.yaml` 与二进制放同一目录。所有项都能用环境变量覆盖，便于容器化/多环境复用同一份文件。

### 3.1 生产环境示例（单机）

```yaml
server:
  port: 8480
  mode: release                     # 生产务必 release
  public_base: https://kefu.example.com   # 对外访问地址，用于生成渠道二维码/接入地址

database:
  driver: mysql
  host: 127.0.0.1
  port: 3306
  user: kefu
  password: 强密码
  name: kefu

jwt:
  secret: 换成足够长的随机串（分布式下所有实例必须一致）
  expire: 24                        # 小时

upload:
  dir: data/uploads                 # 相对工作目录；也可写绝对路径

ip_lookup:
  url: https://ipwho.is/{ip}        # 留空则不解析城市，只显示 IP

redis:
  enabled: false                    # 单机走内存实现；分布式必须 true
  addr: 127.0.0.1:6379
  password: ""
  db: 0
  prefix: "kefu:"                   # 多套环境共用一个 Redis 时用它隔离

push:                               # 厂商推送（APP/桌面离线提醒）
  enabled: false
  apns:   { enabled: false, key_id: "", team_id: "", bundle_id: "", key_file: "", production: false }
  jpush:  { enabled: false, app_key: "", master_secret: "" }
```

### 3.2 环境变量覆盖

| 变量 | 覆盖项 |
|---|---|
| `KEFU_PORT` | `server.port` |
| `KEFU_MODE` | `server.mode` |
| `KEFU_PUBLIC_BASE` | `server.public_base` |
| `KEFU_WEB_DIR` | 前端资源目录（不在二进制同级时用） |
| `KEFU_DB_DRIVER` | `database.driver`（sqlite / mysql） |
| `KEFU_DB_DSN` | sqlite 的 dsn |
| `KEFU_DB_HOST` / `KEFU_DB_USER` / `KEFU_DB_PASSWORD` / `KEFU_DB_NAME` | MySQL 连接 |
| `KEFU_JWT_SECRET` | `jwt.secret` |
| `KEFU_REDIS_ENABLED` / `KEFU_REDIS_ADDR` / `KEFU_REDIS_PASSWORD` / `KEFU_REDIS_DB` | Redis |
| `KEFU_IP_LOOKUP_URL` | `ip_lookup.url` |

> `KEFU_DB_HOST` 只填主机名，端口仍取 `database.port`（DSN 是 `user:pass@tcp(host:port)/db` 分开拼装的，把端口写进主机名会连不上）。

## 4. 数据库准备

### 4.1 建库建号

```sql
CREATE DATABASE kefu DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'kefu'@'%' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON kefu.* TO 'kefu'@'%';
-- 若开启了 utf8mb4 转换，需要 ALTER 权限；也可预先手工执行下面的 SQL
FLUSH PRIVILEGES;
```

### 4.2 表结构

**不需要手工建表**。后端启动时自动：

1. `AutoMigrate` 创建/补齐所有表
2. 把库和已有表统一转成 `utf8mb4`（日志：`[db] 已把 N 张表转换为 utf8mb4`），解决表情符号写入报 `Error 1366`
3. `seed.Run()` 初始化演示数据与账号
4. `seed.BackfillChannelAppID()` 回填历史渠道的 app_id
5. `seed.EnsureDemoAssets()` 生成本地演示素材

### 4.3 初始账号

首次启动日志会打印初始化账号（仅首次创建时）：

| 账号 | 密码 | 角色 | 说明 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 管理后台 `/admin/` |
| `kf01` | `123456` | 客服 | 工作台 `/chat/` |
| `kf02` | `123456` | 客服 | 工作台 `/chat/` |

> 上线后请立刻修改这三个密码（后台「设置」或直接改库 + 用接口重置），并修改 `jwt.secret`。

## 5. 方案 A：单机独立部署

### 5.1 手工启动（先验证能跑通）

```bash
cd /opt/kefu
./kefu-server
```

看到以下日志即成功：

```
数据库就绪: driver=mysql
[cache] redis disabled, using in-memory driver        # 或 redis connected
客服系统后端启动: http://127.0.0.1:8480  (mode=release, redis=false)
```

验证：

```bash
curl http://127.0.0.1:8480/health
# {"code":0,"data":{"ok":true}}
```

三个入口：

| 地址 | 用途 |
|---|---|
| `https://域名/admin/` | 管理后台 |
| `https://域名/chat/` | 客服工作台 |
| `https://域名/kefu/?channel=wechat&uid=xxx` | 用户端（接入链接，可用渠道二维码生成） |

> 根路径 `/` 是**空白页**，属设计如此：三端各自走固定前缀，避免不带参数的访问进入空会话。

### 5.2 注册为系统服务（Linux / systemd）

`/etc/systemd/system/kefu.service`：

```ini
[Unit]
Description=Kefu Server
After=network.target mysql.service

[Service]
Type=simple
User=kefu
Group=kefu
WorkingDirectory=/opt/kefu
ExecStart=/opt/kefu/kefu-server
Restart=always
RestartSec=3
LimitNOFILE=65535

# 敏感配置用环境变量覆盖，避免明文写在 config.yaml
# Environment=KEFU_DB_PASSWORD=强密码
# Environment=KEFU_JWT_SECRET=随机串

StandardOutput=append:/var/log/kefu/app.log
StandardError=append:/var/log/kefu/err.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /var/log/kefu && sudo chown kefu:kefu /var/log/kefu
sudo systemctl daemon-reload
sudo systemctl enable --now kefu
sudo systemctl status kefu
sudo journalctl -u kefu -f          # 看日志
```

### 5.3 注册为 Windows 服务

方式一（推荐）NSSM：

```powershell
nssm install KefuService "C:\kefu\kefu-server.exe"
nssm set KefuService AppDirectory "C:\kefu"
nssm set KefuService AppStdout "C:\kefu\logs\app.log"
nssm set KefuService AppStderr "C:\kefu\logs\err.log"
nssm set KefuService Start SERVICE_AUTO_START
nssm start KefuService
```

方式二：任务计划程序（触发器：开机时；操作：`kefu-server.exe`，起始位置 `C:\kefu`）。

> 不要用 `sc create` 直接注册普通 exe，它不是服务程序，会被 1053 错误拒绝。

### 5.4 Nginx 反向代理（含 WebSocket）

`/etc/nginx/conf.d/kefu.conf`：

```nginx
upstream kefu_backend {
    server 127.0.0.1:8480;
    keepalive 32;
}

server {
    listen 80;
    server_name kefu.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name kefu.example.com;

    ssl_certificate     /etc/nginx/cert/kefu.pem;
    ssl_certificate_key /etc/nginx/cert/kefu.key;

    client_max_body_size 60m;          # 后端单文件上限 50MB，这里留出余量

    # WebSocket：必须带 Upgrade/Connection 头，且不能缓冲
    location /ws {
        proxy_pass http://kefu_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;       # 长连接，别用默认 60s
        proxy_send_timeout 3600s;
        proxy_buffering off;
    }

    # HTTP 接口
    location / {
        proxy_pass http://kefu_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

> 反向代理后，客户真实 IP 来自 `X-Forwarded-For`，后端已支持解析（含内网判定），IP 归属地展示正常。

### 5.5 上线后验证清单

| # | 检查项 | 预期 |
|---|---|---|
| 1 | `curl /health` | `{"code":0,"data":{"ok":true}}` |
| 2 | `/admin/` 登录 admin | 进入后台，11 个菜单可点 |
| 3 | `/chat/` 登录 kf01 | 会话列表渲染，未读角标正常 |
| 4 | `/kefu/?channel=wechat&uid=test1` | 用户端可发消息 |
| 5 | 客服回复后用户端实时收到 | WS 正常（Nginx 头配对了） |
| 6 | 客服刷新页面 | 会话仍是「进行中」，不变「未接待」 |
| 7 | 客服点「退出登录」 | 跳到 `/chat/#/login`，会话回到「待接待」 |
| 8 | 发送带 emoji 的消息 | 成功，不报 1366 |
| 9 | 上传一张图片 | 图片可预览，`data/uploads/` 有文件 |
| 10 | 渠道二维码 | 内容为 `public_base` + 接入路径 |

### 5.6 备份

```bash
# 数据库（含表情符号必须 --default-character-set=utf8mb4）
mysqldump -u kefu -p --default-character-set=utf8mb4 --single-transaction kefu \
  | gzip > /backup/kefu-$(date +%F).sql.gz

# 上传文件
rsync -a /opt/kefu/data/uploads/ /backup/uploads-$(date +%F)/
```

建议 cron 每日执行，保留 14 天；恢复时先建空库再导入（表结构与种子数据会由启动流程补齐）。

## 6. 方案 B：分布式部署

### 6.1 拓扑

```
                    ┌──────────────┐
   浏览器 ──HTTPS──► │    Nginx     │ 静态资源直出 web/
                    │ (负载均衡)   │ /api、/ws 反代
                    └──┬────┬────┬─┘
                       │    │    │
              ┌────────▼┐ ┌─▼──────┐ ┌─▼──────┐
              │ kefu #1 │ │ kefu #2│ │ kefu #3│   无状态后端
              └───┬─────┘ └───┬────┘ └───┬────┘
                  │           │          │
        ┌─────────▼───────────▼──────────▼─────────┐
        │              MySQL（主库）                 │
        └───────────────────────────────────────────┘
        ┌───────────────────────────────────────────┐
        │  Redis（Pub/Sub + 缓存 + 黑名单 + 在线状态）│
        └───────────────────────────────────────────┘
        ┌───────────────────────────────────────────┐
        │  共享存储：data/uploads（NFS / 对象存储）    │
        └───────────────────────────────────────────┘
```

### 6.2 分布式必须调整的配置

每台后端实例的 `config.yaml`：

```yaml
server:
  port: 8480
  mode: release
  public_base: https://kefu.example.com

database:
  driver: mysql
  host: 10.0.0.10            # 内网 MySQL
  port: 3306
  user: kefu
  password: 强密码
  name: kefu

jwt:
  secret: 所有实例必须完全一致   # 否则 A 实例签的 token 到 B 实例被判无效
  expire: 24

redis:
  enabled: true              # 分布式必须开启
  addr: 10.0.0.11:6379
  password: 强密码
  db: 0
  prefix: "kefu:"            # 多套环境共用一个 Redis 时，用不同 prefix 隔离

upload:
  dir: /data/kefu/uploads    # 指向共享存储（NFS 挂载点或对象存储 FUSE）
```

**四条一致性要求**（不一致会出现「偶发掉线/图片 404/登录失效」）：

1. `jwt.secret` 完全一致
2. `redis.addr` + `prefix` 完全一致（否则实例间收不到广播）
3. `upload.dir` 指向同一份共享存储
4. `public_base` 一致、服务器时区一致（`Asia/Shanghai`）

### 6.3 Nginx（静态直出 + 多实例负载均衡）

```nginx
upstream kefu_backend {
    least_conn;                       # 或 round-robin
    server 10.0.0.21:8480 max_fails=3 fail_timeout=10s;
    server 10.0.0.22:8480 max_fails=3 fail_timeout=10s;
    server 10.0.0.23:8480 max_fails=3 fail_timeout=10s;
    keepalive 64;
}

server {
    listen 443 ssl http2;
    server_name kefu.example.com;
    ssl_certificate     /etc/nginx/cert/kefu.pem;
    ssl_certificate_key /etc/nginx/cert/kefu.key;

    client_max_body_size 60m;
    root /var/www/kefu/web;           # 前端产物（每台 Nginx 各放一份）

    # 静态资源直出，带长缓存
    location ^~ /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }
    location ~* ^/(img|favicon\.svg|icons\.svg) {
        expires 7d;
        try_files $uri =404;
    }
    # 上传文件：由共享存储直出，或反代到后端
    location ^~ /uploads/ {
        alias /data/kefu/uploads/;
        expires 7d;
    }

    # WebSocket
    location /ws {
        proxy_pass http://kefu_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;
        proxy_buffering off;
    }

    # 接口 + SPA 入口
    location / {
        proxy_pass http://kefu_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

要不要 `ip_hash` 做会话粘性？**不需要。**

WebSocket 事件通过 Redis Pub/Sub 广播到**所有**实例，每个实例只推给本机持有的连接，因此「客户连在实例 A、客服连在实例 B」也能实时互通。粘性反而会让负载不均。

> 若 Redis 未开启却有多个实例：各实例的广播互相看不见，表现为「消息偶尔收不到、在线状态乱跳」，这是最容易踩的分布式坑。

### 6.4 共享上传目录

三选一：

| 方案 | 说明 |
|---|---|
| NFS | `mount -t nfs 10.0.0.30:/kefu-uploads /data/kefu/uploads`，最简单 |
| 对象存储 + 反向代理 | 后端仍写本地，由定时任务同步；或改造为直传（需改代码） |
| 共享块存储 | 云厂商的 NAS/CFS，多实例同时挂载 |

Nginx 侧用 `alias` 直出，或统一反代到后端 `/uploads`（简单但多吃一次代理）。

### 6.5 滚动升级

```
① 构建新产物 -> 分发到各实例（web/ 与二进制分离，可先换静态）
② 停一个实例（systemctl stop kefu）
③ 替换二进制 + config.yaml
④ 启动并 curl /health 通过后，再处理下一台
⑤ 全部完成后观察错误日志与 WS 连接数
```

注意：

- 数据库变更由 `AutoMigrate` 在启动时执行，**只做增量**（加表/加列/加索引），新旧版本可并存
- 若某次升级涉及删除字段，需先发布兼容版本，再在下个版本删除
- 灰度可用 Nginx `weight` 让新实例承接少量流量

### 6.6 容量参考

| 指标 | 经验值 |
|---|---|
| 单实例并发 WS 连接 | 8k–15k（`LimitNOFILE` 调到 65535） |
| 单实例内存 | 基础 ~120MB，每个 WS 连接约 30–50KB |
| 单实例 CPU | 4C 可支撑数百客服同时在线 |
| Redis 内存 | 每万连接约 30–60MB；`maxmemory-policy allkeys-lru` |
| MySQL 连接数 | 每实例连接池默认 10–20，按实例数 × 20 预留 |

## 7. 安全建议

1. **后端只监听内网**：Nginx 之外的机器不能直连 8480（`firewalld` / 安全组）
2. **改默认口令**：admin/kf01/kf02 三个初始账号、`jwt.secret`、MySQL 与 Redis 密码
3. **上传目录禁止执行脚本**：Nginx 里对 `/uploads/` 加 `location ~* \.(php|jsp|sh)$ { deny all; }`
4. **登录接口限流**（防爆破）：

   ```nginx
   limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
   location = /api/auth/login { limit_req zone=login burst=3 nodelay; proxy_pass http://kefu_backend; }
   ```
5. **HTTPS 必须**：用户端要传手机号/订单信息，明文不可接受
6. **数据库最小权限**：应用账号只给 `kefu` 库的 DML/DDL，不给 `SUPER`/`FILE`
7. **日志脱敏**：`/var/log/kefu/` 权限 640，避免 token 泄漏

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 访问根路径 `/` 是白页 | 设计如此 | 走 `/admin/`、`/chat/`、`/kefu/` |
| 写 emoji 报 `Error 1366 Incorrect string value` | 库/表不是 utf8mb4 | 新版启动会自动转换；手工执行 `ALTER TABLE messages CONVERT TO CHARACTER SET utf8mb4` |
| Windows 双击 exe 报「不是有效的 Win32 应用程序」 | 未 strip 的 cgo 二进制 | `go build -ldflags="-s -w"` |
| 分布式下消息偶尔收不到、在线状态乱跳 | Redis 未启用或各实例 `prefix` 不一致 | 统一 `redis.enabled=true` 与 `prefix` |
| 分布式下图片 404 | `upload.dir` 未指向共享存储 | 挂 NFS / 统一目录 |
| 反代后 WebSocket 连不上 | 缺 `Upgrade`/`Connection` 头或超时太短 | 按第 5.4 节配置，`proxy_read_timeout 3600s` |
| 退出登录后仍显示已登录 | 前端缓存了 token；或 Redis 未启用导致黑名单失效（单机可接受） | 强刷；分布式务必开 Redis |
| 客服刷新页面会话变「未接待」 | 旧版本断连立即释放 | 升级到最新版（断连有 90 秒宽限期，退出登录才立即释放） |
| 用户端接入链接打开空白 | 渠道 `app_id` 与 URL 参数不匹配，或 `public_base` 配错 | 后台「渠道」页重新生成二维码 |
| 上传大于 50MB 报 413 / 提示超过限制 | 后端单文件上限 50MB，Nginx `client_max_body_size` 需 ≥60m | 两侧一起调大 |

## 9. 命令速查

```bash
# 构建
cd web && pnpm install && pnpm build
cd ../server && go build -ldflags="-s -w" -o kefu-server .

# 启动（前台调试）
cd /opt/kefu && ./kefu-server

# 服务管理
systemctl {start|stop|restart|status} kefu
journalctl -u kefu -f

# 健康检查
curl -s https://kefu.example.com/health

# 数据库备份/恢复
mysqldump -u kefu -p --default-character-set=utf8mb4 --single-transaction kefu | gzip > kefu.sql.gz
gunzip < kefu.sql.gz | mysql -u kefu -p --default-character-set=utf8mb4 kefu

# 查看 WS 连接数（粗算）
ss -tn state established '( sport = :8480 )' | wc -l
```
