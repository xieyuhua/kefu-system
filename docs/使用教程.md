## 1. 启动系统

### 1.1 前端：构建产物直接输出到 server/web

前端构建**直接产出到后端静态目录**，不需要手动复制：

```bash
cd web
pnpm install      # 首次会自动创建 server/web 目录
pnpm build        # 类型检查 + 构建，产物落在 server/web
```

产物内容：
```
server/web/
├─ index.html    # 根路径用户端
├─ kefu.html     # /kefu/ 用户端
├─ chat.html     # /chat/ 客服工作台
├─ admin.html    # /admin/ 管理后台
└─ assets/       # 带内容哈希的静态资源（浏览器长期缓存）
```

### 1.2 后端：启动后三个端都可直接访问

```bash
cd server
go run .
```

首次启动会自动建表并写入演示数据，看到下面的日志即成功：

```
数据库就绪: driver=sqlite
[cache] redis disabled, using in-memory driver (single node mode)
[seed] 演示数据初始化完成
[seed] 账号：admin/admin123（管理员）、kf01/123456、kf02/123456
客服系统后端启动: http://127.0.0.1:8480
```

然后直接用浏览器访问：

| 地址 | 端 |
|---|---|
| `http://127.0.0.1:8480/` 或 `/kefu/` | 用户端（客户聊天页） |
| `http://127.0.0.1:8480/chat/` | 客服工作台 |
| `http://127.0.0.1:8480/admin/` | 管理后台 |

> 数据库是 `server/data/kefu.db`（SQLite，零配置）。**删掉这个文件再启动就会重新生成演示数据。**

### 1.3 开发调试（可选）

改前端代码时用开发服务器，带热更新，不用每次 build：

```bash
cd web
pnpm dev        # http://localhost:5173，已代理 /api、/ws 到后端
```

### 1.4 若端口冲突

- 后端换端口：`KEFU_PORT=8481 go run .`
- 前端 dev 同步改代理：`VITE_PROXY_TARGET=http://127.0.0.1:8481 pnpm dev`

## 2. 三个端（独立入口）

系统拆成**三个独立的前端应用**，各自有独立的入口页面、独立的路由、独立的打包文件，可单独部署与鉴权：

| 入口 | 端 | 用途 | 登录 |
|---|---|---|---|
| `http://localhost:5173/` 或 `/kefu/` | **用户端** | 客户聊天页（企微客服风格） | 不需要 |
| `http://localhost:5173/chat/` | **客服工作台** | 接待会话 | 需要 |
| `http://localhost:5173/admin/` | **管理后台** | 配置与统计 | 需要 + 管理员 |

**登录态是共享的**：登录一次，三个端都不用重复登录（token 存在浏览器本地）。

端内路由示例：
```
/admin/#/channels     后台渠道管理
/chat/#/history       工作台历史档案
```

**旧地址会自动跳转**：
- `/c` → `/kefu/`
- `/workbench` → `/chat/`
- `/admin`（无斜杠）→ 自动补成 `/admin/`

演示账号：

| 账号 | 密码 | 角色 | 能做什么 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 全部功能 + 管理后台 |
| `kf01` | `123456` | 客服小李 | 接待「微信客服 + 网页客服」渠道 |
| `kf02` | `123456` | 客服小王 | 接待「企业微信 + APP 客服 + 机器人助手」渠道 |

## 3. 管理员初始化配置（首次必做）

用 `admin` 登录后，右上角「管理后台」进入（或直接访问 `/admin`）。
左侧菜单共 9 项：**概览 / 渠道管理 / 渠道类型 / 自动回复 / 子账号管理 / 客户管理 / 订单管理 / 商品管理 / 设备管理**。

### 3.1 渠道类型（可选，类型可任意自定义）

> **渠道类型不限制枚举**，内置 10 种建议类型（微信客服、企业微信、网页客服、APP 客服、微博、抖音、小红书、快手、邮件、机器人助手），你可以任意增删改。

1. 菜单「渠道类型」→「新增类型」
2. 填写：类型标识 `code`（如 `xiaohongshu`）、显示名（如「小红书」）、颜色、图标（填 emoji 如 `📒`）、排序
3. `code` 留空时会自动用显示名兜底 —— **所以可以直接填纯中文类型名**
4. 已被渠道引用的类型不能删除（会提示「该类型下还有渠道」）

### 3.2 渠道管理

1. 菜单「渠道管理」→「新增渠道」
2. 填写：**类型**（下拉可选内置类型，也**可直接输入任意自定义类型**）、渠道名称（如「小红书店铺客服」）、AppID（可选）
3. 开关说明：
   - **启用**：关闭后该渠道不再接收新会话
   - **机器人自动回复**：开启后，客户消息若没命中自动回复规则，会用兜底话术回复

### 3.2.1 渠道标识 app_id：区分渠道来源与接待

每个渠道都有一个**随机生成的唯一标识**（形如 `kefu_a1b2c3d4`），它是接入链接里区分「渠道来源」的依据：

```
/kefu/?channel=kefu_a1b2c3d4
```

**为什么需要它**：同一渠道类型可以配置多个渠道（比如「微信公众号客服-华东」「微信公众号客服-华南」），
类型和数字 ID 都无法区分，只有 `app_id` 能唯一对应到一个渠道实例，
这样客户从哪个入口进来、消息归因到哪个渠道、分配给哪些客服接待，都是清晰的。

| 操作 | 说明 |
|---|---|
| 新建渠道 | 自动生成随机 `app_id`（表单里可点「随机」重新生成，也可手动改） |
| 编辑渠道 | 可修改 `app_id`，但同租户内必须唯一 |
| 重置 `app_id` | 列表「渠道标识」列的 ⟳ 按钮，生成新值。⚠️ **已分发的链接和二维码会立即失效**，需重新分发 |

表格里「渠道标识 app_id」列支持：
- 复制标识
- 重置（重置前会二次确认，并提示旧链接失效）

> 后端启动时会为**历史渠道**自动补齐 `app_id`（幂等，已有值不动，不会让已分发的链接失效）。
> 补齐后需重新分发链接/二维码。

### 3.2.2 获取渠道二维码与接入地址（复制 / 下载）

渠道列表每行操作列有三个按钮：**二维码**、**地址**、**接待账号**。

**「二维码」** → 弹出窗口：
- 展示该渠道的接入二维码（内容就是用户端接入地址）
- 下方显示完整接入地址，可点「复制地址」
- 尺寸可切 **256 / 320 / 512**
- 点「下载二维码」直接保存 PNG（文件名如 `channel-wechat-微信公众号客服.png`）

**「地址」** → 一键复制完整接入地址到剪贴板。

> ⚠️ 二维码里的地址取自后端配置 `server/config.yaml` 的 `server.public_base`。
> **部署到正式域名后必须改成你的域名**（如 `https://kefu.your-domain.com`），
> 否则扫出来还是本机地址，不是客户能访问的域名。也可用环境变量 `KEFU_PUBLIC_BASE` 覆盖。

### 3.2.3 渠道列表快速设置接待账号

渠道列表操作列的 **「接待账号(数量)」** 按钮 → 弹出窗口勾选该渠道由哪些客服接待：
- 列出所有客服账号，显示在线状态与是否停用
- 勾选后「保存」即生效（全量覆盖）
- 支持「全选」「清空」

> 这里是**从渠道视角**分配客服；§3.3 的子账号管理是**从客服视角**分配渠道。两者改的是同一份数据，任选其一即可。

### 3.3 子账号管理（核心：分配接待渠道）

这是「SAAS 管理员下多个子账号、各自选择接待渠道」的配置位置。

1. 菜单「子账号管理」→「新增客服」
2. 填写：
   - **账号 / 密码**（登录用）
   - 姓名、角色（`agent` 客服 / `admin` 管理员）
   - **最大同时接待数**（超出后不再自动分配）
   - **可接待渠道**（多选，**必填至少 1 个**）
3. 列表里可以直接：
   - 看每个账号当前接待哪些渠道（标签展示）
   - 改「在线状态」（上线后才能被分配会话）
   - 启用/停用（停用后无法登录，且不再接待）
   - 重置密码：编辑时填新密码，留空表示不修改

> **重要**：子账号只能看到「自己被分配的渠道」的会话。这是渠道隔离的核心机制。

### 3.4 自动回复规则（关键词回复 + 转人工）

1. 菜单「自动回复」→「新增规则」
2. 字段说明：

| 字段 | 说明 |
|---|---|
| 规则名 | 便于识别，如「发货咨询」 |
| 适用渠道 | 选「全渠道」或某个具体渠道 |
| 匹配方式 | `包含` / `完全匹配` / `前缀` |
| 关键词 | **多个用英文逗号分隔**，如 `发货,物流,快递,什么时候到` |
| 回复内容 | 命中后机器人的回复（**勾选转人工时留空**） |
| **是否转人工** | 打开后，命中即把会话转为「待接待」并通知该渠道所有客服 |
| 优先级 | 数字越大越优先匹配 |
| 启用 | 关闭则不参与匹配 |

3. 系统已内置 4 条演示规则：问候语、发货咨询、退换货、**转人工**（关键词 `人工,转人工,客服,投诉`，优先级 100）

**匹配顺序**：先匹配「渠道专属规则」，再匹配「全渠道规则」；同级按优先级从高到低。

> 内置的 4 组关键词话术（发货/物流、退款/退货、价格/优惠、你好/在吗）已经**从代码搬到规则表**：
> 启动时会按关键词补齐（已存在同关键词的规则则跳过，不会覆盖你改过的文案），
> 因此现在可以直接在本页编辑这些话术，改完立即生效。

### 3.4.1 AI 应答（可选，默认关闭）

未命中规则时的兜底链路可升级为「检索渠道自动回复内容 + 大模型生成」：

1. 菜单「系统设置 → AI 应答（可选）」填 Base URL / API Key / 模型名 → 点「测试连接」→ 打开开关 → 保存；
2. AI 检索的语料就是「自动回复」页维护的规则（关键词 + 回复内容），按当前渠道过滤，无需单独维护知识库；
3. 任何异常（超时 / Key 失效 / 检索无命中）都会自动降级为兜底话术，客户不会收不到回复。

完整配置步骤与降级行为见 **[AI应答.md](./AI应答.md)**。

### 3.5 商品管理

菜单「商品管理」维护商品，客服接待时可以**直接发商品卡片**给客户。

## 4. 客服：日常接待（工作台）

用 `kf01` 或 `kf02` 登录后进入工作台（`/chat/`）。布局为四栏：

```
[左侧导航] [会话列表] [聊天区] [客户信息栏]
```

### 4.1 顶部状态条

显示「待接待 / 进行中 / 未读」数量，以及 WebSocket 实时连接状态。
右侧按钮：**模拟咨询**（演示用）、**历史档案**、**刷新**。

### 4.2 会话列表：所有渠道合并成一个列表

**所有渠道的会话都合在同一个列表里**，不做渠道切换；每条会话上**标注来源渠道**（渠道色点 + 图标 + 渠道名），并标出会话状态（未接待 / 进行中 / 已结束）。

左侧导航条只剩两个入口：

| 图标 | 作用 | 角标 |
|---|---|---|
| 🗂 | 全部会话（所有渠道合并） | 未读总数 |
| 🔔 | 未接待（所有渠道的待接待合并） | **未接待总数** |

导航条下方列出各渠道图标，仅作**待接待数量参考**（不再用于切换筛选）。

列表顶部：
- 搜索框：按昵称或消息内容搜索
- 状态 Tab：**进行中 / 待接待 / 已结束 / 全部**（均带数量）

每条会话第三行依次标注：**来源渠道** → **客户归属地（📍城市 + IP）** → **会话状态**，鼠标悬停归属地可看完整信息。

### 4.2.1 客户 IP 与归属城市

会话列表、右侧客户资料栏、历史档案（客户详情）都会显示客户的 **IP 地址**和**归属城市**。

- IP 取自客户最近一次访问用户端时的真实 IP（支持 `X-Forwarded-For` / `X-Real-IP`，反向代理后依然准确）
- 城市由 IP 归属地服务解析，**结果缓存 7 天**，解析失败不影响正常接待
- **内网 IP（127.0.0.1、192.168.x.x、10.x.x.x 等）不显示归属地**

> ⚠️ 城市解析需要在后端配置 IP 查询服务，否则只显示 IP 不显示城市：
> 编辑 `server/config.yaml`：
> ```yaml
> ip_lookup:
>   url: http://ip-api.com/json/{ip}?lang=zh-CN     # 或 https://ipwho.is/{ip}
> ```
> 或用环境变量 `KEFU_IP_LOOKUP_URL="http://ip-api.com/json/{ip}?lang=zh-CN"`。
> 该服务需返回含 `city` / `region` / `country` 的 JSON。

### 4.4 聊天区操作
| 操作 | 位置 | 说明 |
|---|---|---|
| **接入** | 待接待会话的按钮 | 领取会话到自己名下（`claim`） |
| **转接** | 标题栏右侧 | 选其他在线客服转交 |
| **结束会话** | 标题栏右侧 | 结束后不可继续回复 |
| 发消息 | 底部输入框 | `Ctrl + Enter` 发送 |
| 发**订单卡片** | 工具栏「🧾 订单」 | 从订单列表选一条发送 |
| 发**商品卡片** | 工具栏「🛍 商品」 | 从商品库选一个发送 |
| 快捷回复 | 工具栏「⚡ 快捷回复」 | 常用话术 |
| 图片 | 工具栏「🖼」 | 选择本地图片 |
| 客户信息 | 右上「收起/展开」 | 显示客户资料 + 历史订单 |

**消息样式**：客户消息在左（白底），客服消息在右（绿色），系统通知居中显示为灰色小条。

### 4.5 右侧客户信息栏

- 客户头像、昵称、来源渠道、**标签**
- 历史订单列表 → 点某条订单可直接以**订单卡片**形式发给客户
- 订单数统计

### 4.6 PC 与移动端自适应

工作台会在三个档位间自动切换（也可随时手动缩放浏览器验证）：

| 屏幕宽度 | 档位 | 布局 |
|---|---|---|
| ≥ 1201px | 桌面 | 图标导航 + 会话列表 + 聊天 + 客户资料栏（四栏并排） |
| 769 ~ 1200px | 平板 | 图标导航 + 会话列表 + 聊天（三栏），客户资料改为**抽屉** |
| ≤ 768px | 移动 | **单栏**：会话列表 ↔ 聊天，点左上角「会话」返回 |

移动端行为：
- 左侧图标导航条自动隐藏，会话列表占满整屏
- 点击会话自动切到聊天页，顶栏出现「会话」返回按钮
- 客户资料、接入/转接/结束按钮改为紧凑样式（文字缩短、图标按钮）
- 顶栏隐藏统计数字，为内容让出空间
- 适配 iOS 刘海屏与底部手势条（`safe-area-inset`）、使用动态视口高度 `100dvh` 避免地址栏导致内容被裁切
- 输入框字号 ≥16px，避免 iOS 聚焦时页面自动放大

平板档位下点击「客户资料」同样以抽屉方式打开。

### 4.7 实时提醒（WebSocket）

新消息通过 WebSocket 实时到达，无需刷新：
- 当前会话 → 直接追加气泡
- 其他会话 → 会话列表未读数 +1
- 断线自动重连（指数退避 1s → 15s）；重连后自动补齐断线期间的消息

### 4.8 模拟咨询（体验用）

点击顶部「模拟咨询」：
1. 选渠道（如「机器人助手」）
2. 填客户昵称、消息内容
3. 发送 → 新会话实时出现在工作台

试试在**机器人渠道**发「什么时候发货」，会自动收到机器人回复；发「转人工」，会话会自动变成「待接待」并提醒你。

## 5. 客服：给客户打标签与备注

标签的目的是**让其他客服下次接待同一客户时，立刻了解客户情况**。

1. 选中会话，展开右侧客户信息栏
2. 在标签区域点击 → 选择或新增标签（标签库由管理员在演示数据中预设：VIP / 高价值 / 价格敏感 / 已退款 / 需回访）
3. 可添加「客户备注」，同样跨客服可见
4. 保存后：**该客户的所有会话、客户管理列表、历史档案里都会显示这些标签**

> 标签变更实时生效，其他客服刷新即可看到。

## 6. 管理员：查看数据统计

菜单「概览」：

- **顶部卡片**：总会话数、接待率、平均消息数/会话、客户数、新增客户、在线客服数
- **最近接待趋势**：折线图（会话数 / 已接待数），可切换 **7 / 14 / 30 天**
- **渠道分布**：各渠道的会话总数、待接待、进行中、已结束，带占比条
- **客服工作量**：每个客服的接待数、结束数、消息数、当前进行中

数据来源：`GET /api/stats/overview?days=N`。

> **统计口径**（避免数字对不上）：
> - 趋势图、渠道分布、客服「消息数」= 所选天数内**新建**的数据
> - 客服的「接待数 / 结束数 / 进行中」= **累计**值
> - 顶部「总会话 / 客户数 / 订单数」= **累计**值
>
> 交叉对账关系：
> - 各客服接待数之和 ≈ 总会话 × 接待率
> - 各渠道会话数之和 = 趋势图区间内会话数之和
>
> 管理员若也亲自接待会话，其工作量会计入表中，姓名旁带「管理员」标签。

## 7. 用户端：把客服接入自己的网站

用户端页面在根路径 `/`（或 `/kefu/`），**所有对接参数通过 URL 的 `?` 后面传递**，运营可以直接拼链接投放，无需开发。

### 7.1 参数说明

> ⚠️ **参数位置**：三端使用 hash 路由，但**接入参数要写在路径之后**（`location.search`）：
> ```
> ✅ http://host/kefu/?channel=web&uid=u1&nickname=王小明
> ❌ http://host/kefu/#/?channel=web&uid=u1     ← 也能读到，但请优先用上面这种
> ```
> 放在 `#` 之后虽然兼容，但会与前端路由混在一起，运营拼链接容易出错。

| 参数 | 必填 | 说明 |
|---|---|---|
| `channel` | ✅ | 渠道标识。推荐填**渠道的 app_id**（如 `kefu_a1b2c3d4`，可在「渠道管理」复制）；也兼容填渠道类型（`wechat`/`web`…）或数字渠道 ID |
| `uid` | | 你业务侧的用户 ID / openid；不传则自动生成游客 ID |
| `nickname` | | 客户昵称，不传显示「游客xxxx」 |
| `avatar` | | 头像 URL |
| `phone` | | 手机号 |
| `order_no` | | 来源订单号，进入后自动带上该订单上下文 |
| `pid` | | 来源商品 ID，进入后自动展示该商品卡片 |
| `scene` | | 自定义场景（如 `product`/`order`/`vip`） |
| `visitor_id` | | 游客追踪 ID |
| `tenant` | | 租户 ID（多租户部署时用；单租户可省略） |

### 7.2 接入示例

推荐用渠道的 `app_id`（从「渠道管理 → 地址/二维码」直接复制）：

```
http://localhost:8480/kefu/?channel=kefu_a1b2c3d4&uid=u_10001&nickname=王小明

http://localhost:8480/kefu/?channel=kefu_9f8e7d6c&uid=o_abc123&nickname=张总&pid=P10087

http://localhost:8480/kefu/?channel=kefu_a1b2c3d4&uid=u_10001&order_no=SO20260305001&scene=order
```

用渠道类型也能用（兼容旧链接，但同类型多渠道时无法区分归属）：

```
http://localhost:8480/kefu/?channel=web&uid=u_10001&nickname=王小明
```

> 也可以在管理后台「渠道管理」点某渠道的**「二维码」/「地址」**直接拿到现成的接入地址（见 §3.2.1）。

中文参数需要 URL 编码，例如「王小明」→ `%E7%8E%8B%E5%B0%8F%E6%98%8E`。

### 7.3 页面行为

1. 打开链接 → 自动创建/复用客户与会话
2. 显示机器人欢迎语「您好，我是智能客服助手…」
3. 若带了 `order_no` / `pid`，顶部自动展示对应**订单卡片 / 商品卡片**
4. 客户发消息 → 命中自动回复规则则机器人回复；命中「转人工」关键词则提示「正在为您转接人工客服」，会话进入客服工作台的**未接待**列表
5. 客服回复后，页面通过 WebSocket **实时**收到（无需刷新）

### 7.3.1 实时与离线补偿

用户端与服务器之间是 **WebSocket** 长连接：

```
ws://<host>/ws/guest?channel=web&uid=u_10001&since_id=0
```

- **在线**：客服回复、机器人回复、转接提示、系统通知实时推送
- **离线也不丢**：所有消息先入库再推送。重新打开页面时会带上 `since_id`（本地记录的最后一条消息 ID），服务端把离线期间的消息**一次性回放**
- **兜底**：若浏览器/网络不支持 WebSocket，前端会自动降级为每 3 秒轮询一次，页面右上角状态区会显示当前连接状态
- 客服端同样是 WebSocket（`/ws?token=...`），断线自动重连并补齐未读

### 7.4 接入调试面板

用户端页面右上角**齿轮图标** → 打开「接入调试面板」：
- 显示当前 URL 及其**解析出的每个参数**（缺失的会标红）
- 可现场修改 `channel` / `uid` / `nickname` 并重新接入
- 「复制接入链接」按钮一键复制当前链接

这是验证 GET 传参最方便的方式。

### 7.5 嵌入自己网站

页面是独立路由，可以直接用 `iframe` 嵌入：

```html
<iframe
  src="https://your-kefu.com/?channel=web&uid=USER_ID&nickname=USER_NAME"
  style="width:400px;height:640px;border:none;border-radius:12px">
</iframe>
```

桌面端会渲染成居中「手机壳」样式，移动端全屏铺满。

## 8. 多端与离线消息

### 8.1 Web / PC 桌面端 / APP

三端共用同一条 WebSocket 通道，只是 `device` 参数不同：

```
ws://host/ws?token=<jwt>&device=web      # 浏览器工作台
ws://host/ws?token=<jwt>&device=desktop  # PC 桌面端（Electron）
ws://host/ws?token=<jwt>&device=app      # APP
```

### 8.2 注册推送设备（APP / PC 端）

APP / PC 桌面端启动后调用一次注册接口，把推送 Token 告诉服务端：

```http
POST /api/devices
Authorization: Bearer <客服的 JWT>
Content-Type: application/json

{ "device": "app", "platform": "ios", "push_token": "a1b2c3...", "name": "iPhone 15" }
```

| 参数 | 取值 |
|---|---|
| `device` | `app` / `desktop` / `web` |
| `platform` | `ios` / `android` / `windows` / `mac` |
| `push_token` | 厂商下发的推送 Token（PC 桌面端一般留空，只走 WebSocket） |
| `name` | 设备名，后台「设备管理」列表展示用 |

登出、卸载、换机时注销：`DELETE /api/devices/:id`。

后台「设备管理」页可查看本账号已注册的全部设备（Token 脱敏显示）、注销设备，并**发送测试推送**验证厂商通道是否接通。

> 📖 完整对接步骤（各厂商 SDK、APNs 密钥、离线补偿策略、常见问题）见 **[推送对接.md](./推送对接.md)**。
> 服务端配置在 `server/config.yaml` 的 `push` 段；未启用厂商时网关只记日志，提醒仍会落库、端侧重连后可补拉。

### 8.3 离线消息同步

客服离线期间的消息**照常入库**，不会丢失。重新上线后：

```bash
# 增量拉取离线消息（since_id = 端侧已收到的最大消息 ID）
GET /api/offline/messages?since_id=0

# 拉取离线期间的系统提醒
GET /api/offline/notifications?since_id=0
```

端侧本地保存返回的 `latest_id`，下次重连时作为 `since_id` 传入，即可增量补齐。
**回复走 HTTP 接口**（`POST /api/conversations/:id/messages`），不依赖长连接，弱网可直接重试。

## 9. 常见问题

**Q：登录提示「账号已被停用」？**
管理员在「子账号管理」里把该账号停用了，重新启用即可。

**Q：客服登录后看不到任何会话？**
检查两件事：① 该子账号是否分配了「可接待渠道」；② 该渠道下是否有会话。子账号只能看自己渠道的会话。

**Q：模拟咨询后没有机器人回复？**
机器人回复只在**渠道开启了「机器人自动回复」**，或**命中了自动回复规则**时触发。去「渠道管理」打开开关，或去「自动回复」加规则。

**Q：发了「转人工」但没有客服收到？**
转人工只是把会话置为「待接待」并通知该渠道客服。客服需要**在线**（子账号管理里改在线状态）且**分配了该渠道**才会看到。

**Q：8480 端口启动失败？**
端口被其他程序占用（例如某些软件自带的 Web 服务）。用 `KEFU_PORT=8481 go run .`，前端用 `VITE_PROXY_TARGET=http://127.0.0.1:8481 pnpm dev`。

**Q：Windows 下 `./kefu-server.exe` 报「不是此操作系统平台的有效应用程序」？**
PowerShell 对同名目录/可执行文件解析的问题。直接用 `go run .` 启动，或用完整路径 `& "E:\workspace\kefu\server\kefu-server.exe"`；最稳妥是 `go run .`。

**Q：想清空数据重新开始？**
删掉 `server/data/kefu.db`，重启后端即重新生成演示数据。

**Q：三个端能分开部署吗？**
可以。构建产物是**多页应用**，四个 HTML 各自独立，可以分开部署到不同域名：

```
dist/
├─ index.html    # 根路径用户端
├─ kefu.html     # /kefu/ 用户端
├─ chat.html     # /chat/ 工作台
├─ admin.html    # /admin/ 后台
└─ assets/       # 三端共用的静态资源
```

Nginx 配置（放在同一域名下）：
```nginx
root /var/www/kefu;

# 用户端（根路径 + /kefu/）
location = /     { try_files /index.html =404; }
location /kefu/  { try_files /kefu.html =404; }
# 客服工作台
location /chat/  { try_files /chat.html =404; }
# 管理后台（可额外加 IP 白名单 / 基础认证）
location /admin/ { try_files /admin.html =404; }

# 接口与实时通道
location /api/   { proxy_pass http://127.0.0.1:8480; }
location /ws     { proxy_pass http://127.0.0.1:8480; proxy_http_version 1.1;
                   proxy_set_header Upgrade $http_upgrade;
                   proxy_set_header Connection "upgrade"; }
location /assets/ { expires 7d; }
```

也可以让**后端直接托管**（默认方式，`pnpm build` 已把产物输出到 `server/web`）：

```bash
cd web && pnpm build      # 产物直接落在 server/web，无需复制
cd ../server && go run .
# 然后访问 http://127.0.0.1:8480/ 、/kefu/ 、/chat/ 、/admin/
```

**Q：扫码后打开的还是 127.0.0.1？**
改后端 `server/config.yaml` 的 `server.public_base` 为你的正式域名，重启后端后重新生成二维码（见 §3.2.1）。
⚠️ 该值必须与实际服务端口/域名一致（例如 `https://kefu.example.com`），
**不要填 5173**（那是 `pnpm dev` 的开发端口，只在本地改前端时用）。

**Q：生产环境怎么部署？**
- 前端：`cd web && pnpm build`（产物直接输出到 `server/web`）
- 后端：`go build -o kefu-server .` 后直接运行（会自动定位同级 `web/` 目录）；改 `config.yaml` 切 MySQL
- 若要用 Nginx：把 `server/web` 作为静态根目录，按 §9 的配置反代 `/api`、`/ws`
- 多实例：开启 Redis（`config.yaml` 的 `redis.enabled: true`）以共享 Pub/Sub 广播与 Token 状态

详见 `README.md`。

## 附：接待规则与交互细节（最新）

### 未读与统计的实时性

工作台顶部的「待接待 / 进行中 / 未读」和列表里的未读角标**都是 WebSocket 实时推送**，不需要手动刷新：

- 客户发来消息 → 未读 +1、会话上浮，约 250ms 内出现在列表
- 客服回复 → 该会话未读清零
- **待接待会话点开不清未读**：必须先点「接入」把会话变成「进行中」，未读才会清零（先认领、再处理）
- 正在查看的会话收到新消息 → 不计未读（自动标记已读）

### 客户互斥接待

同一个用户（按 `uid` 跨渠道判定）被某个客服接入后：

- 其他客服的列表里**自动移除**该用户的全部会话（含其他渠道的）
- 其他客服强行领取会提示「该客户已由其他客服接待，请勿重复接入」
- **管理员不受限制**，始终可见全部会话

### 客户在线状态

小圆点表示客户是否在线，判定依据是**访客端 WebSocket 连接**：

- 访客页面打开（WS 建连）→ 在线
- 关闭页面 / 断网 → 宽限 15 秒后置为离线（刷新、切后台不会误判）
- 客户在线但长时间不说话仍显示在线（以连接为准，不靠「最后活跃时间」）

### 移动端对话列表

- **左滑**会话行 → 露出「删除」按钮，点击后二次确认（归档，客户再咨询会自动恢复）
- 向右滑或点击行本身 → 收起滑动状态

### 模拟新咨询（演示用）

- 仅**管理员**可见、可调用；子账号工作台不显示该按钮，接口也会拒绝
- 用于本地演练「客户发起新咨询」的完整链路

### 上传相关

- 图片/视频/文件上传显示「上传中」进度条，失败可点击重试
- 大文件（> 4MB）自动走**分片上传 + 断点续传**（2MB/片）
- 单文件大小上限：后台「系统设置 → 上传文件大小上限（MB）」，默认 50MB
- 用户端图片支持**双指缩放**查看

### 访客身份生成规则

首次进入且未提供 `uid` 时由服务端生成：

- `uid` = `visitor_<yyMMddHHmmss><4位随机hex>`，例如 `visitor_2610221530118730`
- 昵称为空时：游客显示 `游客_<HHmmss>`；带业务 `uid` 的显示该 `uid`

### 自动回复什么时候生效（后台开关）

后台「系统设置 → **已接待的会话不再自动回复**」（默认开启）：

| 场景 | 机器人是否回复 |
|---|---|
| 客户首次咨询，还没人接待 | ✅ 会（按关键词规则 / AI / 兜底话术） |
| 客服已接入或已回复过 | ❌ 不会，由人工接待 |
| 客服已接待，之后客服离线（会话被释放回待接待） | ❌ 不会（这一轮已归人工） |
| 客服点了「结束会话」，客户再次咨询 | ✅ 会（属于新一轮咨询） |
| 会话被归档后客户再来 | ✅ 会（同上） |

> 如果希望「只要在待接待状态就让机器人回复」（不区分是否接待过），把该开关关闭即可。
