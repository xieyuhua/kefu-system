# 商品卡片 & 订单卡片 对接文档

> 适用版本：当前版本已支持。用户端进入客服会话时，可通过 URL 参数自动携带**订单卡片**或**商品卡片**，
> 进线后**弹窗让用户确认是否发送给客服**（可关闭），用户确认后客服在工作台消息流看到对应卡片，回复更精准。

---

## 一、功能概览

| 卡片 | 触发参数 | 数据来源 | 展示位置 |
|---|---|---|---|
| 订单卡片 | `order_no` | 后台「订单管理」已录入的订单 | 确认弹窗 → 确认后进入消息流 |
| 商品卡片 | `pid` | 后台「商品管理」已录入的商品 | 确认弹窗 → 确认后进入消息流 |

- **用户端**：进线带卡片时，先弹出「是否发送给客服」确认框（电商咨询效果）。点「发送给客服」卡片才作为消息发出；点 ✕ 或「不需要」则不发送。
- **客服端**：用户确认发送后，卡片出现在该会话的消息流里（带「查看详情」入口）。

---

## 一·补充：卡片确认弹窗交互

进线时若链接携带 `order_no` / `pid`，用户端会弹出确认框：

```
┌─────────────────────────┐
│ 发送给客服            ✕ │
│  ┌───────────────────┐ │
│  │  订单/商品卡片预览  │ │
│  └───────────────────┘ │
│ 是否将该订单发送给客服？ │
│   [不需要]  [发送给客服] │
└─────────────────────────┘
```

三种选择：

| 操作 | 结果 |
|---|---|
| 点「发送给客服」 | 卡片作为 `type=order` / `type=product` 消息发出，进入对话流，客服可见 |
| 点右上角 ✕ | 关闭弹窗，**不发送**，卡片清空 |
| 点「不需要」 | 同上，不发送 |

> 若同时携带订单与商品，弹窗内两张卡片一起展示，确认后依次发送。

## 二、卡片数据结构（后端下发）

`GET /api/guest/init` 响应的 `data.order` 与 `data.product` 字段，为 JSON 对象或 `null`。

### 订单卡片 `order`

```json
{
  "order_no":   "SO20260305001",   // 订单号（唯一）
  "title":      "2026春季新款 纯棉圆领T恤",
  "status":     "待发货",          // 订单状态（文本）
  "amount":     199.00,            // 金额
  "quantity":   2,                 // 数量
  "created_at": "2026-03-05 14:20:00",
  "image":      "/uploads/...jpg", // 商品/订单图
  "sku":        "T-S-001"
}
```

### 商品卡片 `product`

```json
{
  "id":    "P10086",               // 商品对外 ID（唯一，即 pid 参数）
  "title": "2026春季新款 纯棉圆领T恤",
  "price": 199.00,
  "image": "/uploads/...jpg",
  "stock": 100,
  "sku":   "T-S-001",
  "url":   "https://你的商城/p/P10086"   // 点击「查看详情」跳转
}
```

> 字段名与后台「订单管理」「商品管理」的录入字段一一对应，无需二次映射。

## 三、用户端 URL 对接

### 3.1 携带订单卡片

```
http(s)://<host>/kefu/?channel=<渠道>&uid=<用户ID>&nickname=<昵称>&order_no=SO20260305001
```

### 3.2 携带商品卡片

```
http(s)://<host>/kefu/?channel=<渠道>&uid=<用户ID>&nickname=<昵称>&pid=P10086
```

### 3.3 参数说明

| 参数 | 必填 | 说明 |
|---|---|---|
| `channel` | 是 | 渠道标识：渠道类型（`wechat`/`web`/`app`…）或渠道 `app_id`（`kefu_xxx`） |
| `uid` | 否 | 业务侧用户 openid / user_id，不传自动生成游客 ID |
| `nickname` | 否 | 用户昵称 |
| `order_no` | 否 | 订单号，需与后台「订单管理」里录入的 `order_no` **完全一致** |
| `pid` | 否 | 商品对外 ID，需与后台「商品管理」里录入的 `pid`（商品 ID）**完全一致** |
| `scene` | 否 | 场景标识，建议填 `order` / `product`，可用于自动回复分流 |

### 3.4 完整示例（带签名）

```
http(s)://<host>/kefu/?channel=web&uid=u_10001&nickname=王小明&order_no=SO20260305001&scene=order&visitor_id=v_8899&sign=xxxx
```

## 四、数据准备（后台录入）

### 4.1 订单（管理后台 → 订单管理）

录入字段需包含：

| 字段 | 说明 |
|---|---|
| `order_no` | 订单号，**唯一**，与 URL 参数 `order_no` 匹配 |
| `title` | 订单标题（卡片主标题） |
| `status` | 订单状态（任意文本，如「待发货」「已发货」） |
| `amount` | 金额 |
| `quantity` | 数量 |
| `image` | 商品/订单缩略图 URL |
| `sku` | SKU |
| `customer_id` | 关联客户（用于「历史订单」聚合） |

### 4.2 商品（管理后台 → 商品管理）

| 字段 | 说明 |
|---|---|
| `pid` | 商品对外 ID（如 `P10086`），**唯一**，与 URL 参数 `pid` 匹配 |
| `title` | 商品标题 |
| `price` | 价格 |
| `image` | 商品图 |
| `stock` | 库存 |
| `sku` | SKU |
| `url` | 商品详情页链接（卡片「查看详情」跳转目标） |

## 五、客服端使用

1. 客户带卡片进线并**确认发送**后，卡片作为消息进入该会话的消息流，客服工作台直接可见。
2. 客服也可在输入框工具栏点击 **🧾 订单** / **🛍 商品** 按钮，主动从客户历史订单 / 商品库中选择卡片发送。
3. 卡片消息的 `message.content` 是 JSON 字符串（与 `order`/`product` 对象同结构），前端按 `type=order` / `type=product` 渲染。

## 六、常见问题

**Q1：带了 `order_no` 但用户端没弹卡片确认框？**
- 确认该订单已录入后台，且 `order_no` 与 URL 参数**逐字符一致**（含大小写、无空格）。
- 确认 `channel` 参数正确（渠道不存在会直接报「渠道不存在」）。

**Q2：带了 `pid` 但卡片是空的？**
- 确认商品 ID 用的是对外 `pid`（如 `P10086`），不是数据库自增主键。

**Q3：卡片图片不显示？**
- 图片 URL 需可被浏览器直接访问（建议用本系统 `/uploads/...` 或公网 HTTPS 地址）。
- 若用本系统上传，路径形如 `/uploads/20260305/xxx.jpg`，前端会自动拼接当前域名。

**Q4：能否同时携带订单和商品？**
- 可以，`order_no` 与 `pid` 同时传即可，确认弹窗里两张卡片一起展示，用户确认后依次发送。

**Q5：用户叉掉弹窗，客服还能看到卡片吗？**
- 不能。叉掉 / 点「不需要」即表示**不发送**，卡片不会进入会话，客服端也看不到。
- 这是有意的隐私设计：由用户决定是否把具体订单/商品暴露给客服。

**Q6：客服交接班能看到客户卡片吗？**
- 能。只要用户确认发送过，卡片随消息存储，任何客服打开该会话都能看到，与「标签备注」一样跨客服可见。
