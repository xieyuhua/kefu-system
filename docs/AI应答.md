# AI 应答使用说明

> 适用版本：内置「关键词规则 → AI 应答 → 兜底话术」三级应答链路。
> 默认**关闭**：不配置时机器人行为与以前完全一致（命中规则回复，否则回兜底话术）。

---

## 1. 这套能力解决什么问题

原来的应答链路只有两级：

```
命中自动回复规则  →  用规则的文案回复
未命中            →  统一回「兜底话术」（robot.fallback_reply）
```

客户问「耳机保修多久」这类**规则没覆盖、但确实有标准答案**的问题，只能拿到一句兜底话术。
开启 AI 应答后，链路变成三级：

```
① 命中自动回复规则          → 规则文案（不变，命中次数照常累加）
② 未命中 → AI 应答          → 检索「该渠道的自动回复规则」，把最相关的几条内容交给大模型组织回答
③ AI 不可用 / 检索无命中     → 兜底话术（客户始终能收到回复）
```

关键设计：**AI 只能看该渠道的自动回复内容**。检索不到相关内容就不猜，直接回兜底话术（也不会产生模型调用费用）。

> 语料来源 = 后台「自动回复」页维护的规则（关键词 + 回复内容），**不再有独立的知识库**。
> 一条规则既是「精确关键词命中」的回复，也是 AI 检索的片段 —— 一处维护、两处生效。

## 2. 三步配置（后台「系统设置 → AI 应答（可选）」）

### 2.1 填连接参数

| 字段 | 填什么 | 例子 |
|---|---|---|
| Base URL | OpenAI 兼容接口的**根地址**（不要带 `/chat/completions`，后端会自己拼） | `https://api.deepseek.com/v1` |
| API Key | 服务商控制台里的 Key | `sk-xxxxxxxx` |
| 模型名 | 服务商文档里的模型标识 | `deepseek-chat` |
| 超时（秒） | 单次请求上限，超时即降级为兜底话术 | `20` |
| 系统提示词 | 约束模型「只依据自动回复内容回答、不确定就说转人工」 | 用默认值即可 |

常见服务商填法：

| 服务商 | Base URL | 模型名示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 阿里云百炼（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 本地 vLLM / Ollama（兼容层） | `http://127.0.0.1:8000/v1` | 按部署的模型名 |

### 2.2 点「测试连接」

按钮会用表单里的值真实发一条极短请求（`max_tokens=8`），验证**地址 + 鉴权 + 模型名**。
结果直接显示在卡片底部：

- `连接成功，模型可用` → 配置没问题，可以保存并启用；
- `接口返回 401：...` → Key 不对或没有权限；
- `AI 接口不可用：请求 ... 失败: dial tcp ...` → 地址不通（内网服务请确认服务器能访问）；
- `未配置模型名（ai.model）` → 少了必填项。

> 「测试连接」只验证连通性，**不会保存任何配置**；要落库请点「保存」。

### 2.3 打开开关并保存

勾选「启用 AI 应答」→「保存」。保存后立即生效（无需重启）。

> 提示：`API Key` 保存后页面只显示 `******`。之后只想改超时或模型名时，**Key 留空即可**，
> 后端会沿用已保存的 Key；提交 `******` 也是同样效果。

## 3. 维护检索语料（后台「自动回复」菜单）

AI 检索的语料就是**自动回复规则**，一条规则 = **规则名 + 关键词 + 回复内容**，检索时三者都参与打分：

| 字段 | 作用 | 写法建议 |
|---|---|---|
| 规则名 | 命中权重最高，写「这条规则解决什么问题」 | `退货政策`、`发货时效`、`蓝牙耳机质保` |
| 关键词 | 逗号分隔的同义词，问题里直接出现时加权最明显 | `退货,退款,售后` |
| 回复内容 | 模型组织回答的依据，写**可以直接复述给客户的口径** | 「支持 7 天无理由退货，签收后 7 天内可申请……」 |

维护要点：

- **短句、结论先行**：回复内容前 30 字把结论说清楚（模型会优先复述前半段）；
- **一条规则只讲一件事**：把「退货」「换货」「运费」拆成多条，检索命中率更高；
- **同义改写放进关键词**：客户可能说「退钱」「不想要了」，关键词里补上 `退款`、`退货`；
- **停用而不是删除**：临时下架某条政策时关掉「启用」开关，该规则立即不再参与检索；
- **转人工规则不参与 AI 检索**：勾选「转人工」的规则走人工链路，不会被当成 AI 语料；
- **渠道过滤**：AI 只检索**适用于当前会话渠道**的规则（含全渠道规则），渠道专属话术不会串台。

检索打分口径（想调参时看这里）：

```
中文按 2-gram 切分 + 单字覆盖率，英文/数字按词切分；
命中规则名/关键词比只命中回复正文更相关；关键词在问题里原样出现时额外加分；
最终分数归一化到 0~1，低于 rag.min_score（默认 0.15）视为无命中。
```

## 4. 降级行为（重要）

AI 是「锦上添花」，任何异常都不会让客户收到空回复：

| 场景 | 客户端收到 | 服务端日志 |
|---|---|---|
| `ai.enabled=false`（默认） | 兜底话术 | 无（不打日志，避免刷屏） |
| 已启用但配置不全（少 base_url/api_key/model） | 兜底话术 | `[ai] ... 配置不完整 ... 降级为兜底话术` |
| 自动回复规则无命中（全部低于 `rag.min_score`） | 兜底话术 | `[ai] ... 自动回复规则无命中（阈值 0.15，问题：...）` |
| 接口超时 / 401 / 5xx / 返回体解析失败 | 兜底话术 | `[ai] ... 调用模型失败（命中 N 条规则），降级为兜底话术: <原因>` |
| 渠道未开启机器人 | 不回复（与改造前一致） | — |
| 模型返回空文本 | 兜底话术 | `[ai] ... 模型返回空文本` |

另外两条硬约定：

1. **检索无命中不调模型**：既避免编造答案，也避免白花 token（假服务调用计数可用于验证这一点）；
2. **回复文案不加「AI 生成」前缀**，消息仍以 `sender_role=robot` 落库与广播，头像 / 展示样式不变。

想调整严格程度：

- 想让 AI 少答一点（更保守）：把 `rag.min_score` 调高（如 `0.3`）；
- 想让 AI 多答一点（覆盖面优先）：调低到 `0.1`，同时把 `rag.top_k` 保持 `3` 左右，
  片段太多会稀释重点、也更贵。

## 5. 自行验证（本地无真实 Key 时）

用一个假的 OpenAI 兼容服务即可验证整条链路：

```bash
# 1) 任意一个返回固定文案的本地服务，监听 19100，提供 POST /v1/chat/completions
# 2) 后台把 ai.base_url 指过去、随便填一个 Key、打开开关
# 3) 客户问一个自动回复规则里有的问题（如「耳机保修多久呀」）
#     → 机器人回复 = 假服务返回的文案
# 4) 把 ai.base_url 改成不可达地址（如 http://127.0.0.1:19999/v1）
#     → 机器人回复 = 兜底话术，服务端日志里有 [ai] ... 降级为兜底话术: <原因>
```

## 6. 常见问题

**Q：开了 AI，原来的关键词话术还在吗？**
在。命中自动回复规则依然优先（规则里的文案、命中次数、转人工都不变）。AI 只处理「未命中」的那部分。
内置的 4 组关键词话术（发货/物流、退款/退货、价格/优惠、你好/在吗）已经落成自动回复规则，
可以在后台「自动回复」页直接编辑，改完立即生效。

**Q：自动回复规则要维护很多吗？**
不必。先把高频问题（退换货、发货时效、保修、发票、运费）各写一条，观察日志里
`自动回复规则无命中` 的客户问题，再按需补规则即可。

**Q：会不会把客户的隐私内容发给大模型？**
发出去的只有「命中的自动回复片段 + 客户这条问题」。如果接的是公有云模型，请评估这一点；
对合规要求高的场景可以把 `ai.base_url` 指向内网自建模型。

**Q：AI 回答错了怎么办？**
两种手段：① 修正对应的自动回复规则（模型只会复述规则内容）；② 把 `rag.min_score` 调高，
让 AI 更少介入，交给人工客服。
