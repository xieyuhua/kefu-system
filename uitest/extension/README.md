# UI 自动化录制器（Chrome / Edge MV3 插件）

浏览器端的**录制端**：把你手工点的每一步操作（点击、输入、下拉、勾选、上传、跳转）变成平台可回放的
测试步骤，并为每个元素写入稳定的定位标识 `data-uitest-id`。回放由服务端 `uitest-server` 的内置浏览器执行。

- 服务端接口契约：`docs/API.md`（唯一标准，字段名 snake_case）
- 共享定位运行时：`runtime/uitest-keys.js`（插件与 Go 执行器共用同一份，保证定位算法一致）

---

## 一、目录说明

```
extension/
├── manifest.json     # MV3 清单：权限、content_scripts 顺序、service worker、popup
├── uitest-keys.js    # 共享运行时（由主流程从 runtime/ 同步而来，不要手改）
├── content.js        # 录制内容脚本：监听 DOM 事件、生成步骤、浮层反馈
├── background.js     # service worker：所有 HTTP 请求、会话状态、导航记录、角标
├── popup.html        # 弹窗结构（宽 340px，中文 UI）
├── popup.js          # 弹窗逻辑：开始/停止、备注、开关、最近录制
├── popup.css         # 弹窗样式（主色 #4f46e5，无任何外部资源）
└── README.md         # 本文档
```

文件职责边界：

| 文件 | 负责 | 不负责 |
|---|---|---|
| `content.js` | 采集 DOM 事件、生成 Step、浮层与高亮 | 任何网络请求、状态持久化 |
| `background.js` | 全部 `fetch`、`chrome.storage.local["uitest_state"]` 写入、导航步骤、角标 | 页面 DOM 操作 |
| `popup.js` | 只发消息、渲染状态、展示错误 | 直接写会话状态 |

> `uitest-keys.js` 不需要自己创建，由主流程从 `runtime/` 目录同步到 `extension/` 下。
> 若缺失，插件仍能安装，但录制功能不可用，浮层会提示「录制运行库 uitest-keys.js 未加载」。

## 二、安装（加载已解压的扩展）

1. 确认 `extension/` 目录里 `manifest.json`、`uitest-keys.js`、`content.js`、`background.js`、
   `popup.html`、`popup.js`、`popup.css` 都已就位。
2. 打开扩展管理页：
   - Edge：地址栏输入 `edge://extensions`
   - Chrome：地址栏输入 `chrome://extensions`
3. 右上角打开「开发人员模式 / 开发者模式」。
4. 点击「加载解压缩的扩展（加载已解压的扩展程序）」，选择整个 `extension/` 目录。
5. 建议把插件固定到工具栏（拼图图标 → 固定），方便随时打开弹窗。
6. **修改代码后**：回到扩展管理页点该插件的「重新加载」，然后**刷新被录制页面**（内容脚本只在页面加载时注入）。

默认服务端地址 `http://127.0.0.1:8490`；如改过端口，在弹窗「服务端地址」里填写并点「测试连接」。

## 三、录制流程

1. **打开业务页面**（例如后台商品列表页）→ 点击插件图标打开弹窗。
2. 弹窗顶部圆点应为**绿色**（服务端 `/api/health` 可用）。红色请先看「常见问题」。
3. 填「录制名称」（如「新建服务商品」）→ 点「开始录制」。
   - 插件会 `POST /api/recordings` 建一条录制，并记住当前标签页。
   - 页面右下角出现浮层：`● 录制中 · N 步` + 「停止」按钮。
4. **正常操作页面**：点击按钮、填输入框、选下拉、勾选、上传文件、跳转页面……
   - 每录到一个元素会闪一下 2px 靛蓝色描边；
   - 浮层步数实时增长；工具栏角标显示当前步骤数；
   - 同一输入框连续输入只记 1 步（500ms 防抖 + 服务端 PATCH 合并），不会产生几十条中间态。
5. **补备注（强烈建议）**：弹窗「上一步备注」写清这一步的业务含义（例如「在商品名称输入框填入测试商品名」），
   点「保存备注」。备注越清楚，执行时的定位与自愈越准。
6. 需要记录回车提交时，打开弹窗里的「回车键也记录」开关（默认关闭）。
7. 点「停止录制」（弹窗里红色按钮，或页面右下角浮层的「停止」）。
   - 插件 `PATCH /api/recordings/{id}` 置为 `draft`；
   - 该录制进入弹窗「最近录制」列表（最多 10 条，点击直接打开控制台详情页）。
8. 到控制台 `http://127.0.0.1:8490/#/recordings` 检查步骤、补断言、生成数据、执行。

录制期间会自动记录：

| 用户操作 | 生成的 action |
|---|---|
| 标签页加载 / 跳转（含 SPA 路由导致的新 URL） | `navigate` |
| 点击按钮、链接、可交互元素 | `click` |
| 文本输入（含 textarea、contenteditable） | `input` |
| 下拉选择 | `select` |
| 勾选 / 取消勾选 | `check` / `uncheck` |
| 文件选择 | `upload` |
| 回车（开关打开时） | `key` |

明确**不记录**：粘贴过程中的中间态（只认防抖后的最终值）、`scroll`、`mousemove`、
插件自己的浮层与高亮元素（`data-uitest-ignore`）、点击页面空白处（`html` / `body`）。

## 四、元素稳定 ID 原理（2.0 重建安全）

每个录制到的元素都会写上一个属性：`data-uitest-id="ut_xxxxxxxx"`。

1. **确定性算法**：`ut_<fnv1a32(语义指纹)>`，指纹只取
   `tag / type / 稳定id / 稳定name / aria-label / placeholder / label / 表单项标题 / 表格列名`
   这类"业务上不太会变"的语义信息，**不含 DOM 层级、不含随机数、不含构建产物**：

   | 会被过滤掉（每次打包都变） | 例子 |
   |---|---|
   | CSS Modules / scoped hash 类名 | `.product-card_1a2b3c`、`.css-9f8e7d`、`.sc-bdVaJa` |
   | 作用域属性 | `data-v-7ba5bd90` |
   | 组件库自动 id / name | `el-id-3812-12`、`:r1:`、`input-3`、`rc_select_7` |

   页面重新打包只要**业务语义没变**（标题、按钮文字、列名还在），key 就不变；
   同一页面里签名相同的元素会自动加 `_2/_3` 后缀去重，保证 key 唯一且跨构建顺序一致。

2. **定位链（按"重建后是否还可靠"排序）**：
   `uid` → `attr`(`data-testid`/`data-test`/`data-cy`) → `id`/`name`（仅稳定时）
   → `label`(表单项标题) → `near`(标题 → 同一表单项里的控件)
   → `role`(角色+按钮文字) → `cell`(表格行文字+按钮文字) → `text`
   → `placeholder` → `css`（纯结构路径，不含 class） → `xpath`。

   按钮类元素**只走** `cell`/`role`/`text`：按钮文字如果走 `label` 会被当成表单项标题，
   进而抓到旁边的输入框。

3. **自愈定位**：全部失败时用录制时保存的元素指纹（`step.target`：tag/type/label/placeholder/
   aria/文本/表单项标题/列名/name/test_attr）在页面上打分，**唯一最高分且 ≥5 分**才命中，
   运行日志标记 `healed=true`；可用 `POST /api/runs/{id}/heal` 把新定位回写录制。
   另外「执行时自动刷新过期的 uid」打开后，靠兜底命中的新 uid 会自动写回。

4. **元素库**：录制时顺手上报 `POST /api/elements/bind`（key = `data-uitest-id`），
   控制台可查看命中次数、上次出现时间、是否失效。

5. **和平台配合的推荐做法**：
   - 关键元素让前端加 `data-testid`（控制台里被标红「缺 testid」的就是建议补的），
     它会被当成仅次于 uid 的最高优先级；
   - 录完在录制详情点一次「一键刷新定位」，把定位统一升级成 uid；
   - 业务页面重新打包后跑一次 `go run ./cmd/scenarios -only 重新打包` 就能验证跨版本是否还命中。
## 五、常见问题（FAQ）

**Q1：插件连不上服务端（圆点是红色）。**
- 先确认服务端是否在跑：浏览器打开 `http://127.0.0.1:8490/api/health`，应返回 `{"ok":true,...}`；
- 确认端口就是 **8490**（改了端口要在弹窗里同步改地址并点「测试连接」）；
- 地址写成 `http://127.0.0.1:8490` 或 `http://localhost:8490` 都可以，插件会自动去掉尾部 `/`；
- 若提示「无法连接服务端」，多为服务端未启动或被占用，重启服务端后再点「测试连接」。

**Q2：页面刷新后 uid 还管用吗？**
管用。`data-uitest-id` 由算法确定性计算，不依赖运行时随机量，刷新后同一元素重算得到同一个 key；
即便页面把属性清掉了，执行器也会先 `markAll()` 补齐再定位。

**Q3：点「开始录制」了但页面没有任何反应？**
- 内容脚本只在页面加载时注入：**安装/重载插件后需要刷新被录制页面**；
- 只对 `http://` / `https://` 页面生效，`chrome://`、扩展页、PDF 阅读器内部不生效；
- 确认录制是在弹窗所在窗口的**当前标签页**发起的（切换标签页后请重新开始录制）。

**Q4：文件上传怎么回放？**
浏览器安全策略不允许脚本伪造本地文件，插件只记录文件名并标注
`note = "文件上传需在服务端执行时提供本地文件路径"`。请在该步骤的备注/数据准备里提供
服务端（执行器所在机器）上真实存在的文件绝对路径。

**Q5：密码框为什么只记录了 `{{password}}`？**
密码属于敏感信息，录制时直接脱敏为 `{{password}}` 变量并标注「已脱敏，执行时由数据准备注入」。
在控制台为本次执行生成数据集时提供 `password` 字段的真实值即可。

**Q6：一个输入框为什么有时会变成两条步骤？**
只有在连续输入**同一个元素**（同一 `data-uitest-id`）且中间没有任何其它动作时才会合并。
如果中途点了别的地方、换了元素或者防抖窗口被跨过，就会各自成为一条独立步骤，这符合预期。

**Q7：Selenium/执行器报"元素未找到"怎么办？**
先看运行日志里 `locator_used` 与 `healed`：若 `healed=true` 说明是自愈命中，建议在控制台点
「回写自愈定位」把新定位固化；若彻底找不到，回到录制里给该步骤补一句清晰备注，或重新录制该步骤。

**Q8：录制时插件的浮层/描边会不会被录进去？**
不会。浮层放在 Shadow DOM 且 host 为 `uitest-overlay-host`，点击事件会按 `composedPath()`
排除；高亮框、浮层元素都带 `data-uitest-ignore`，事件过滤时整棵子树跳过。

**Q9：这里没有图标文件？**
是的，仓库未提供图标，`manifest.json` 里没有声明 `icons`，浏览器会使用默认占位图标，不影响功能。

**Q10：iframe 里的元素能录吗？**
能。内容脚本以 `all_frames: true` 注入所有框架，iframe 内的点击/输入同样会生成步骤，并且会在
`locator.frame_url` 里写上该框架地址；浮层只在顶层框架显示，避免多个浮层叠在一起。
需要说明的是：目前服务端执行器以主框架定位为主，iframe 内的步骤建议在控制台确认或改写定位。
